# 工具管理

底栏「配置」→「工具」是全部工具的统一管理页：内置工具、MCP 服务器动态注册的工具、你自己新建的工具都在这里，一处看清「模型现在能用什么」，也一处控制「哪些工具该出现在哪一轮」。

自动化任务的创建、编辑、启停和删除，以及项目/全局工具授权规则，直接显示在本页下方，不再有独立页面。

## 页面上有什么

页面默认打开「工具箱」：选择常用模板或已保存工具、填写参数，检查命令与风险后点「运行」，直接显示真实输出、退出码、工作区和截断状态，不经过聊天模型。页面同时保留 MCP、脚本、自定义工具、定时任务与权限页签。在这个页签中，按来源分三组，组内按名称排序：

| 分组 | 来源 | 能改什么 |
| --- | --- | --- |
| 自定义工具 | 你自己新建的 | 名称之外的都改：描述、参数、命令模板、超时、注入方式、关键词 |
| 内置工具 | App 自带的（`readFile` / `Bash` / `websearch` 等） | 描述、注入方式、关键词，以及参数 schema 中兼容的说明元数据 |
| MCP 工具 | MCP 服务器提供的（名字以 `mcp__` 开头） | 同上；原始参数结构仍由服务端决定 |

每行显示「名称 + 描述 + 注入方式徽标」。徽标一共三种：

- **每轮注入**（默认）：每一轮都进工具列表；
- **关键词注入**：只有当前这条用户消息命中关键词时才进；
- **关闭**：不进入发给模型的工具列表（徽标置灰）。这只是注入设置，不等于撤销工具执行权限；权限仍由现有授权策略决定。

点任意一行打开详情面板；顶栏「＋」先选择自定义命令工具、脚本工具或 MCP 服务器；自定义工具左滑可以删除（内置与 MCP 工具不能删，左滑按钮是灰的）。

## 编辑内置与 MCP 工具的参数说明

详情面板区分**原始 schema**与**当前 schema**。前者用于对照工具实际支持的参数；后者可编辑并保存兼容的说明覆盖，也可以重置为原始 schema。保存后的说明会进入实际发给模型的工具定义，不只是改面板上的展示。

只允许修改 `description`、`title`、`examples`、`$comment` 这类说明元数据。**参数名、类型、必填项、枚举值等结构不能改**，也不能靠改 schema 让工具多出执行能力。结构改动会被拒绝；确实需要不同参数或命令时，请新建自定义工具。

保存时会校验，运行时也会重新对照原始 schema。如果 App 升级或 MCP 服务更新导致原有覆盖不再兼容，会使用工具当前的原始 schema，而不是继续给模型一份错误的参数契约。覆盖说明不会改变流式输出、执行逻辑或原有权限检查。

## 工具箱直接使用与导入

工具箱可直接运行模板，不必先注册到 AI 工具列表。选择与填写参数只生成预览，点击「运行」才执行；取消会停止等待并丢弃旧结果，不回滚命令已产生的副作用。依赖缺失或权限拒绝会保留错误，不自动安装、不将未知退出码当成功。

「导入工具 JSON」接收原有单条工具格式：先粘贴 JSON，点「解析并预览」，确认后保存。同名或与已注册工具冲突时不覆盖，请改名后重新预览。选择工具后可导出 JSON、复制或分享。导入和保存本身不执行命令。

「编辑器设置」打开既有编辑器配置；补全、诊断等仍在真实代码编辑器中使用，语言服务需已安装，设置页不是语言服务运行成功的证明。

## 从实用模板开始

模板不再常驻工具列表。点顶栏「＋」选择新建自定义工具，在创建表单中展开「实用模板」后选择，再检查参数和命令；不选择模板也可以直接填写。编辑已有工具时不显示模板选择，避免意外覆盖已有配置。工具分类栏固定在同一位置，MCP 重连操作放在对应分类内容内。

可用的可编辑模板：

| 模板 | 用途 |
| --- | --- |
| `build_android` | 执行一个 Android Gradle 任务，返回日志尾部、退出码及完整日志路径 |
| `build_rust` | 执行 `cargo build` 并保存完整日志 |
| `build_python` | 在当前工程构建 Python wheel 并保存完整日志 |
| `build_logs` | 查询当前容器、当前工作区最近完成的构建日志 |
| `git_status` | 查看 Git 工作区状态 |
| `git_diff` | 查看 Git 差异 |
| `git_log` | 查看 Git 提交记录 |
| `find_files` | 查找文件 |
| `rtk_command` | 在已安装 RTK 的环境中调用输出过滤命令 |
| `code_check` | 文件或目录的 Kotlin／Rust 词法和括号检查，Python 另做 AST 语法检查；不是编译或类型验证 |
| `code_symbols` | 提取文件或目录的限额符号列表 |
| `code_callers` | 按名称查询词法调用点候选，不是完整语义调用图 |
| `code_map` | 使用内置轻量工具查看 Kotlin、Rust、Python 的限额代码地图 |
| `codegraph_status` | 查询当前环境已经安装的 CodeGraph 状态，不安装、不建索引 |
| `codegraph_index` | 使用已安装的 CodeGraph 在当前工作区建立索引，会写文件并占用资源 |

**管理页选择模板只填入新建编辑器，保存后才注册为模型工具；工具箱则可以预览后直接手动运行**，不会自动启用一批工具或安装依赖。模板预设为关键词注入并带有相关关键词，不会默认每轮全部注入；保存前可以修改描述、参数、命令、关键词和注入方式，命令仍走现有执行器与授权链。

[RTK 官方说明](https://github.com/rtk-ai/rtk)介绍了 Git 状态、差异与日志、文件检索、测试输出过滤，以及回查原始输出的用法。过滤效果取决于具体命令和输出，不能保证固定的 token 节省比例。模板不会替你安装 RTK；未安装时会保留底层「找不到命令」错误，不会静默改跑其他命令。需要回查时按官方用法查看原始输出，不把过滤摘要当作完整证据。

### 代码地图与可选代码图

本地环境随 App 提供轻量代码查询，不需要 Node 或另一个模型密钥。初始化容器后，可让 AI 查符号、代码地图或调用点候选，也可在终端执行：

```sh
aharou-code status
aharou-code symbols --path app/src --name Example
aharou-code map --path app/src --limit 80
aharou-code callers --path app/src --name example
```

AI 先按需发现代码结构工具，才展开其完整参数；展开状态按会话和工作区隔离，不会因为别的会话查过代码就常驻注入。较久未使用的会话可能需要重新发现。重启后也需重新发现。

这是一份**当前文件的限额结构快照，不是完整语义调用图**：Python 使用 AST，Kotlin/Rust 使用轻量结构提取；同名、重载、宏、反射、跨语言调用可能不完整，调用点只能作为候选。它不运行源码、不编译、不安装依赖；不能替代原搜索、编辑器诊断或构建验证。每次重新读取当前文件，不复用旧索引；结果带内容指纹，超过文件数、大小、扫描时间或输出限额时明确标记部分结果。优先指定子目录或符号，避免反复全仓扫描。小文件的结构元数据可能比原文更大；已知路径和相关行时直接读文件，不机械地先查地图。节省效果取决于任务，不能保证固定比例。

远程 SSH 主机不自动同步这些命令；未部署时保留原搜索、文件读取与诊断，不声称环境已就绪。

[CodeGraph](https://github.com/colbymchenry/codegraph) 是可选的独立工具，不捆绑进 APK，也不通过模板自动下载。先在目标环境按官方固定版本安装并验证兼容性，再保存状态或索引模板。安装、建立索引、连接 MCP 是三件不同的事；状态查询不能证明调用图完整。索引和第三方运行时可能占用较多资源，具体体积、Android 兼容性与节省效果尚未测量。

需要向 AI 提供图查询时，使用现有 MCP 页面导入以下配置，启动前检查工具已在 **MCP 实际执行的容器** 中安装；SSH 工作区的 stdio 后端与普通命令可能不同，详见 [MCP 服务器](./mcp)：

```json
{"mcpServers":{"codegraph":{"command":"codegraph","args":["serve","--mcp"]}}}
```

配置不包含密钥，不自动授权；第三方工具继续走 MCP 权限和按需发现。首次查询前确认目标仓库与索引状态，不把 CodeGraph 推荐的受影响测试列表当成完整 CI 的替代品。不要同时为同一工作区启动多个索引写入服务。

### 编译工具与日志目录

先在目标容器里用 `aicode` 安装对应开发环境，再从上述模板保存工具。执行时继承当前工作区的容器或 SSH，不另配一份编译器路径；远程主机必须已安装相同命令，不会自动同步或安装。

也可以在终端的项目目录执行：

```sh
aharou-build android :app:assembleArmsoloDebug
aharou-build rust
aharou-build python
aharou-build logs
```

Android 参数是一个任务名，必须按实际项目修改；项目的构建授权和检查脚本仍照常生效。Python 使用 `python3 -m pip wheel --no-deps . -w dist`，构建后端仍可能按工程声明下载构建依赖。

本地默认将手机 `/storage/emulated/0/log` 映射为 `/root/log`，日志按容器、工作区分目录，每次构建使用独立文件。日志工具只返回最近完成的一次，未完成或被中断的日志不会冒充成功结果。默认回传最后 80 行与退出码，完整内容按返回路径读取；构建命令的失败退出码保持不变。

共享存储不可写时自动使用 App 私有持久目录并在运行日志中告警；映射和私有目录均不可用时，构建命令仍执行并返回原始输出和退出码。日志不会自动清理，请按需自行管理。目录设置及覆盖方法见[容器与镜像](./container)。

**这里只收集由 `aharou-build` 启动的标准输出和错误输出，不接管所有软件，也不自动收集整机 logcat。** 不主动记录完整环境和命令参数，但第三方编译输出仍可能包含凭据、源码或本地路径，不承诺自动脱敏。共享目录里的日志可能被其他具有存储权限的应用读取；敏感项目可通过容器挂载或环境变量改用私有目录。

## 新建一个自定义工具

自定义工具 = **一段 JSON 参数表** + **一条 shell 命令模板**。模型调用时，App 把你的模板里的占位符换成模型给的参数值，在当前执行环境（本地容器或远程 SSH）里真实执行，输出直接回给模型。

填写顺序建议照下面来：

1. **名称**：模型按这个名字调用，只能用字母、数字、下划线、连字符，最长 64 位。创建后不能改名（改名等于换成一个新工具）。
2. **描述**：告诉模型「这工具做什么、什么时候用」。写得越具体，乱调越少。
3. **参数（JSON）**：一个对象数组，每项四个字段：

   ```json
   [
     {
       "name": "path",
       "type": "string",
       "description": "要统计行数的文件路径",
       "required": true
     }
   ]
   ```

   `type` 支持 `string` / `integer` / `number` / `boolean`；`required: true` 的参数模型不给就会被拦下并报「缺少必需参数」。面板里有「插入示例」按钮，点一下就有模板可以改。
4. **执行命令**：用 <code v-pre>{{参数名}}</code> 引用参数，例如：

   ```sh
   wc -l {{path}}
   ```

   执行前每个占位符都会被替换成 **shell 单引号转义** 后的参数值，所以参数里带空格、单引号、中文都不会把命令拆坏。参数值里的 <code v-pre>{{...}}</code> 也不会被二次展开。
5. **超时（秒）**：1~600，默认 60。超时会强制终止命令。
6. **注入方式 / 关键词**：见下一节。

### 命令模板的几条硬规则

为了避免「以为参数生效了、其实跑的是半条死命令」，下面这些情况会直接报错，不会执行：

- 命令里**一个占位符都没有** → 允许（固定命令，如 `df -h`）；只是参数一定不会生效，面板会提示你；
- 命令引用了**参数表里没声明的占位符**（例如把 <code v-pre>{{path}}</code> 打成 <code v-pre>{{pth}}</code>）→ 报错；
- **必需参数缺失**或全是空白 → 报错，模型会收到「缺少必需参数: xxx」并自己改正；
- 命令为空 → 报错。

可选参数不传时替换成空字符串 `''`，命令结构不会被破坏。

### 安全边界

自定义工具的每次调用**都要经过一次工具授权确认**（和你用 `Bash` 时一样）：确认框里的标题就是渲染后的完整命令，看一眼就知道模型要跑什么。授权弹窗支持「始终允许」，但被安全策略判定为敏感的调用仍会逐次确认。

换句话说：**能改命令模板的只有你自己**，模型只能往里填参数值，且参数值一律按字面量转义，没法靠参数把命令改成另一条。

## 注入方式：三种状态

每个工具单独设置，决定「这一轮要不要把它交给模型」。

| 状态 | 语义 |
| --- | --- |
| 每轮注入 | 进每轮的工具列表（默认） |
| 关键词注入 | 当前这轮**用户消息**（不含 AI 自己说过的话）命中任一关键词时才注入 |
| 关闭 | 不进工具列表 |

关键词的匹配口径：

- **大小写不敏感**（`Deploy` 能命中 `deploy`）；
- **忽略空白**（关键词里的空格、换行都不参与匹配，`git log` 与 `gitlog` 等价）；
- **子串匹配**（用户消息里包含关键词就算命中，不需要整句相等）；
- **关键词为空时按「每轮注入」处理**——避免你填了关键词模式却忘了写关键词，工具从此永远不出现。

关键词在输入框里用**逗号或空格分隔**，中英文逗号都认。

典型的用法：把「部署上线」「数据库迁移」这类不常用又敏感的自定义工具设成关键词注入，平时不占工具列表的位置，只有你真的提到它时模型才看得到。

## 条目存在哪

配置沿用仓库既有的「文件资产」范式（和自定义提示词、技能一致），一个工具一个文件，可以用文件管理器直接改、也能进版本库：

```
<配置根>/tools/custom/<名称>.json    一条自定义工具
<配置根>/tools/overrides.json        内置与 MCP 工具的描述 / 注入方式 / schema 说明覆盖
<工作区>/.aharou/tools/...           同结构，项目层
```

- **项目层优先、全局层兜底**：同名条目两层都有时，工作区里的那份生效。
- 有打开的工作区时，新建与修改写到该项目层；没有工作区时写全局层。
- 删除会把两层里的同名文件一起清掉，不会出现「删了又冒出来一条」。
- 单个文件写坏了（手改 JSON 出错）只影响那一条，其余工具照常工作，坏的那条会被跳过并记进日志。

## 出问题怎么办

| 现象 | 原因与处理 |
| --- | --- |
| 工具列表里看不到刚建的工具 | 检查注入方式是「关闭」还是关键词模式但关键词没命中当前这句话 |
| 模型从不调用某个自定义工具 | 描述太笼统，模型不知道什么时候该用；把「什么时候用」写进描述 |
| 调用时报「缺少必需参数」 | 参数标了 `required`，但模型没给值；可以把它改成可选，或在描述里写清格式 |
| 调用时报「占位符未声明」 | 命令里的 <code v-pre>{{x}}</code> 和参数表里的 `name` 对不上 |
| 保存失败 | 名称不合法（只能是字母数字下划线连字符）、参数 JSON 不是数组、执行命令为空——面板会就地标红 |
| 内置或 MCP 工具的 schema 不能保存 | 检查 JSON 是否有效，是否改动了参数名、类型、必填项、枚举等结构；只保留说明元数据改动，或重置为原始 schema |
| 更新后 schema 说明没有应用 | 原始参数结构可能已变化；对照新的原始 schema 重新编辑，不要复制旧的参数结构 |
| RTK 模板提示找不到命令 | 当前执行环境未安装 RTK；模板不自动安装，也不自动切换命令 |

## 离线逆向与安全审计

### 安装离线分析环境

在 App 容器终端运行 `aicode`，进入「环境安装」，选择「授权离线逆向分析」。确认清单后，只补装缺少的 `readelf`、`objdump`、`strings`、`file`、Java 和 Python 3；`jadx`、`apktool` 分别询问，默认跳过。工具已可用时不会重复安装，不默认安装 Ghidra，也不更换容器镜像。

该场景使用当前容器的 apk、apt、dnf、yum、pacman 或 xbps 软件源，按当前架构查询包后再安装，适用于 ARM64。安装过程需要访问软件源；「离线」指后续对已授权样本的分析，不代表安装无需联网。仓库、架构缺包或查询失败会明确显示「不可用」并返回失败，不会悄悄添加第三方软件源或下载反编译器压缩包；安装命令成功但所需工具仍找不到，也不会报告就绪。未选择的可选工具会保留「不可用（未安装）」状态。

安装场景只配置工具，不读取、解压或执行用户样本；自动探测也只查找命令，不启动分析工具。SSH 主机须在其自身环境准备这些命令，本地容器装好不代表远程主机可用。

### 使用内置审计技能

可让 agent 加载内置 `security-audit` 技能，对你明确授权的本地文件做静态检视。它提供文件 SHA-256、ELF/PE/DEX 头字段、ZIP/APK 候选的目录统计，以及 SQL、XSS、CSRF、SSRF、命令、路径、XML、隐私、权限和自启动等源码复核线索。不会联网扫描、执行样本、解压归档、读取凭据，也不会安装反编译器或改变现有工具权限。

本地初始化会将配套资源放到 `~/.aharou/builtin-skills/security-audit/`，脚本为 `scripts/audit.py`；先确认文件已出现再按技能命令运行。SSH 工作区在加载内置技能前，将配套文件同步到工作区绑定主机的 home 下 `.aharou/builtin-skills/`，不写入自定义技能目录；连接变化或同步失败会返回明确错误，不会假装已部署或扫描。工具发现只检查可用命令，不执行它们。APK 候选不是签名验证或清单解码，正则命中不是已证实漏洞，零命中也不是安全证明；超限、截断与未覆盖内容都会单列。

安全术语按真实分析意图合并，不用换名来绕过授权。上游适配只记录边界：DSH 的 MIT/宿主依赖不代表可以盲装；VCP 的 CC BY-NC-SA 代码不复制进 GPLv3 项目；Windows 专用且许可证未知的 skill 不导入 Android。DSH 与 VCP 的公开许可证已核对；Windows 项目的独立许可未确认。没有复制上游代码，本工具包为原创实现。

## Session observability

`sessions` adds `action=tool_calls` for redacted persisted tool receipts in a session belonging to the current workspace. Supply `session_id` (defaults to the current session), optional exact `tool`, `status` (`SUCCESS`, `ERROR`, `PARTIAL`), inclusive epoch-millisecond `after` / `before`, `limit` (up to 200) and nonnegative `offset`. Results include `nextOffset`; `null` means the final page. Newest-first offset pagination is live, so concurrent new calls may shift pages. Receipts are retained for the existing 30-day window; they are not a complete permanent audit history. Denied calls have an empty status and remain visible without a status filter. Full output and build-authorization bodies are not returned by this action.

`action=context` returns the latest in-process final workflow request composition for the current session only, after stored-tool folding and privacy masking, subject to the same workspace ownership check as session reading. An explicit ID for another session is rejected even within the same workspace. It returns counts and fixed section identifiers, never prompt headings or injected bodies. Estimated tokens are a local character heuristic, not provider usage. Workspace boundaries remain enforced for both actions.
