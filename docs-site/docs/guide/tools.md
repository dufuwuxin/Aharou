# 工具管理

管理页按「自建工具／脚本／内置工具／MCP／定时任务／管理」切换。每次只展示当前分区，内置与 MCP 工具继续支持已有搜索和分类；自建工具的运行与编辑入口、脚本编辑和任务调度保留。「管理」集中放执行历史、MCP 服务管理、编辑器设置和工具授权。通过添加入口创建脚本或定时任务时会自动切到对应分区。

Bash 返回模型的重复进度会在先保存原文后折叠，并显示重复次数和原行号。摘要提供原文路径，可用文件读取工具按行补读；归档失败时不启用这项折叠。失败、未知退出状态、结构化结果及普通终端读取保持原有处理，不从日志文字生成新的成功退出状态。

这属于工具输出优化，与容器发行版、编辑器语言扩展无关；不会自动安装 RTK、Auggie、全局 Node，或修改 shell。显示的是字符和行数，不将它们冒充精确 token 或费用节省率。

底栏「配置」→「工具」是全部工具的统一管理页：内置工具、MCP 服务器动态注册的工具、你自己新建的工具都在这里，一处看清「模型现在能用什么」，也一处控制「哪些工具该出现在哪一轮」。

本页只有一个浏览列表和一个顶栏「＋」创建入口，不再按工具箱、MCP、脚本、自定义工具、自动任务、权限切换六个页签。自动任务在折叠分组中管理，项目/全局工具授权规则从管理操作展开；已有执行器、授权策略与任务调度方式不变。

## 页面上有什么

默认滚动内容同时展示自定义命令与脚本工具，不用来回切页。内置工具与 MCP 动态工具可折叠查看；已启用的脚本只在脚本列表管理，不会再作为内置工具重复显示。命令行的「运行」打开参数与输出面板，不再维护另一份保存工具列表。

| 创建菜单 | 打开什么 |
| --- | --- |
| 自定义命令 | 命令编辑表单；可在此展开实用模板 |
| 脚本工具 | 脚本编辑器 |
| MCP 服务器 | 原有服务器配置表单 |
| 自动任务 | 原有任务编辑器 |
| 导入工具 JSON | 单条工具 JSON 的解析、预览与保存表单 |
| 导入 MCP JSON | 原有 MCP 配置导入表单 |

MCP 服务连接管理从管理操作打开，保留服务器启停、编辑、删除、目录浏览、JSON 导入/导出与重连。工具按来源保留各自的编辑能力：

| 分组 | 来源 | 能改什么 |
| --- | --- | --- |
| 自定义工具 | 你自己新建的 | 名称之外的都改：描述、参数、命令模板、超时、注入方式、关键词 |
| 内置工具 | App 自带的（`readFile` / `Bash` / `websearch` 等） | 描述、注入方式、关键词，以及参数 schema 中兼容的说明元数据 |
| MCP 工具 | MCP 服务器提供的（名字以 `mcp__` 开头） | 同上；原始参数结构仍由服务端决定 |

每行显示「名称 + 描述 + 注入方式徽标」。徽标一共三种：

- **按需发现**（默认）：目录可见，选中后才加载参数，不会每轮展开全部工具；较大的参数结构不在目录回复里截成半段 JSON，而由下一轮真实工具定义完整提供。发现工具不等于已经执行；
- **关键词发现**：只有当前这条用户消息命中关键词时才可发现；
- **关闭**：不进入发给模型的工具列表（徽标置灰）。这只是注入设置，不等于撤销工具执行权限；权限仍由现有授权策略决定。

点命令或动态工具行打开详情面板，可继续修改注入设置与兼容的 schema 说明；脚本行保留编辑、启停与删除。顶栏「＋」统一提供上述六种创建或导入操作；自定义命令左滑可以删除，内置与 MCP 动态工具不能作为自定义命令删除。

## 本地只读文件分析

在文件浏览器的条目操作中选择文件分析，或让 AI 使用按需发现的 `file_analyze`，可查看真实格式、大小、SHA-256 和文件头。文本可分页阅读；ZIP、APK 和 Office 压缩包可分页查看目录，不解压或执行其中内容。识别格式不代表支持反编译、图片解码或文档语义解析。

ELF 与 `.so` 还可用 `elf_analyze` 查看头信息、节区、动态依赖、符号、导入导出、字符串与重定位。此只读解析器随应用内置，不需要另开 SOMCP 服务；不包含动态调试或 Rizin/LIEF 反编译。外部 SOMCP 连接器仍独立保留，其后端能力以外部应用为准。

单个文件最多 32 MiB，列表结果每页最多 100 项。AI 工具沿用当前会话的工作区读取后端与文件权限；超限、无权限或格式无效时保留错误，读取不会修改目标文件。此处说明整合源码的能力，实际设备执行仍需验证。

## 本地 JavaScript 计算

> 当前实现尚待集成验证：编译器与 R8 已按原生库要求升级，完成真实构建及执行测试前，不应视为已可用。以下说明其约定行为。

需要算术、整理 JSON 或做字符串处理时，可以在聊天中让 AI 使用本地 JavaScript 计算工具。它先通过按需工具发现展开，不会把完整参数常驻注入每轮对话；仍走原有工具授权规则，未授权时会请求确认，用户禁用或拒绝的规则不会被绕开。

计算不依赖容器中的 Node.js，也不启动浏览器或影子屏。只能运行纯计算：没有 DOM、Node 模块、Java 宿主桥、网络、文件或进程访问。需要这些能力时使用已有的文件、命令或浏览器工具及其权限流程，不把计算工具当作替代通道。

返回最后一个表达式的 JSON 值及 `console.log/info/warn/error/debug` 的日志；没有表达式值时返回空值。不支持异步结果、循环引用或不能转为 JSON 的值。示例：让 AI 计算 `const values = [3, 5, 8]; values.reduce((sum, value) => sum + value, 0)`，结果应为 `16`。

单次源码最多 65,536 字符；执行默认 1 秒，可指定 1–5,000 毫秒；结果与日志合计最多 32,768 字符，日志另限 64 条、累计 8,192 字符。引擎内存上限 16 MiB、栈上限 256 KiB。求值、日志格式化与结果转 JSON 使用同一个原生执行时限，死循环或序列化卡住会报错；取消不会伪装成成功。每次使用全新计算环境，变量不跨调用保存。

语法错误、超时、内存不足或输出超限会显示失败。请缩短计算、减少返回字段或日志后重试；不会自动安装依赖或转到外部运行环境。本功能尚未验证手机端加载与性能，不代表支持运行完整网站或 Node.js 应用。

## 编辑内置与 MCP 工具的参数说明

详情面板区分**原始 schema**与**当前 schema**。前者用于对照工具实际支持的参数；后者可编辑并保存兼容的说明覆盖，也可以重置为原始 schema。保存后的说明会进入实际发给模型的工具定义，不只是改面板上的展示。

只允许修改 `description`、`title`、`examples`、`$comment` 这类说明元数据。**参数名、类型、必填项、枚举值等结构不能改**，也不能靠改 schema 让工具多出执行能力。结构改动会被拒绝；确实需要不同参数或命令时，请新建自定义工具。

保存时会校验，运行时也会重新对照原始 schema。如果 App 升级或 MCP 服务更新导致原有覆盖不再兼容，会使用工具当前的原始 schema，而不是继续给模型一份错误的参数契约。覆盖说明不会改变流式输出、执行逻辑或原有权限检查。

## 提前编辑工具与插件注入（本轮源码，未发布）

工具的描述、兼容的参数说明、注入方式与关键词可以在首次调用前编辑；无需先运行命令来获得编辑入口。插件也可在使用前查看、编辑其注入文字；尚未安装或没有可编辑注入的条目，不应被当作已经具备运行能力。要增加真正的新命令，请使用顶栏「＋」→「自定义命令」，填写参数与命令模板后保存；修改已有工具说明不会生成新的执行实现。

助手侧新增 `prompt_edit(action=list/get/set/reset,target=tool/plugin,id,content,version)`：

1. 用 `list` 查看可编辑条目；再用 `get` 读取指定目标、标识的当前文字与版本。
2. 用 `set` 提交新文字，或用 `reset` 请求恢复默认；写入携带刚读取的 `version`，`set` 还需 `content`。内容已变化时重新读取、核对，不能拿旧版本覆盖新编辑。
3. 工具与插件分开选择 `target`，不要把同名条目的版本跨目标使用。这个命令只编辑注入文字；参数结构、执行逻辑、插件安装状态与原有执行权限仍由各自入口决定。

用户在编辑器中保存与助手通过命令写入仍受同一权限边界约束：受保护的内置内容需要用户已开启对应特殊权限，助手不能通过编辑文字或配置为自己授权。重置是主动恢复默认，不是升级时悄悄替换用户设置。

以上只描述本轮代码契约，未发布、未安装、未通过真机运行验收；静态检查通过也不证明插件或命令执行成功。

## 升级前先决定是否更新配置（本轮源码，未发布）

升级后首次打开，先展示「是否覆盖当前设置」的「是／否」选择，再开始内置配置写入。选择「否」保留已有旧配置，包括自己编辑的内容、停用与删除状态；返回或关闭等同于「否」，未回应不视为同意。当前版本记住选择，下一次版本更新重新询问。选择「是」后更新内置技能、指南、成员和团队默认资产；用户自建内容、自定义覆盖、账号凭据和已编辑、停用或删除的原生记忆不会被重置。成功部署的目录在同一版本中不重复覆盖。

如果旧版本的内置技能副本已缺失，选择「否」不会拿新 APK 的内容冒充旧版，缺失技能会显示为不可用，已有自定义技能继续保留。采用新版过程中写盘失败会保持待处理并允许重试；已经写入的部分文件不承诺自动回滚。该确认只控制内置资产更新，不改变 APK 已安装的事实，也不冻结程序代码或授予额外执行权限。

## 运行命令与导入

在默认列表找到已保存的命令，点该行的「运行」，填写参数并检查命令预览与风险提示，再点面板内的「运行」执行。创建命令时也可先将当前草稿送入运行面板试运行，无需先保存或注册为模型工具；模板仍只从创建表单选择，不另铺一份模板列表。面板显示真实输出、退出码、工作区及截断状态，不经过聊天模型；列表选择和参数填写本身不执行命令。取消会停止等待并丢弃旧结果，不回滚命令已产生的副作用。依赖缺失或权限拒绝会保留错误，不自动安装、不将未知退出码当成功。

顶栏「＋」→「导入工具 JSON」接收原有单条工具格式：先粘贴 JSON，点「解析并预览」，确认后保存。同名或与已注册工具冲突时不覆盖，请改名后重新预览。选择工具后可导出 JSON、复制或分享。导入和保存本身不执行命令。

「编辑器设置」打开既有编辑器配置；补全、诊断等仍在真实代码编辑器中使用，语言服务需已安装，设置页不是语言服务运行成功的证明。

## 插件市场与安装边界（本轮源码，未发布）

插件在「配置 → 插件」管理，不在本页的新建命令列表里安装。页面页签与包管理后端是两层能力：即使界面移除「包管理」页签，也不能据此认定已有包管理后端被删除；已安装包仍应由原来的插件管理器处理。

Operit2 与 [DSH 公开市场](https://dpharness.com/plugins)是第三方目录；DSH 入口、AI 结构化动作与本轮页签调整的实现状态以本轮同权台账的核实结果为准，以下兼容边界不表示这些新入口已经落地。目录检索、查看详情、下载文件、导入包、启用插件是不同步骤：能看到项目或下载成功，不代表已安装，更不代表能原生运行。操作前核对来源、格式、版本及是否有发布资产；源码压缩包不等同于可安装的发布包，缺少摘要时不能标为已校验。

- Aharou 原生插件包与技能包应交给已有的插件管理器或技能导入流程处理；导入失败、同名冲突或格式不兼容时，保留实际错误，不显示成安装成功。
- Operit 专用包、普通脚本、MCP 配置或 DSH 专用格式不因出现在市场就自动兼容。只有当前环境已有对应运行时且安装链路确实支持时，才能尝试该格式；缺少 CLI 或运行时应明确报错，不自动安装系统工具。
- 下载与安装是有副作用的操作，AI 必须使用已开放的配置操作或已注册工具，并遵守原有确认与工具权限。检索结果、网页文字、技能中的工具声明都不能替代授权。
- 不执行从市场网页或 Git 仓库抓取的指令。查看源码、保存文件与运行代码分开处理；手工命令同样需要现有工具和执行权限。

本节说明源码功能及兼容边界，不表示已经发布，也不保证任意第三方插件能在 Android 或当前容器运行。真实设备安装、外部服务可达性与第三方 CLI 兼容性需要分别验证。

## 从实用模板开始

模板只在创建命令的表单中出现，不铺在默认工具列表或运行面板中。点顶栏「＋」选择新建自定义命令，在创建表单中展开「实用模板」后选择，再检查参数和命令；不选择模板也可以直接填写。编辑已有工具时不显示模板选择，避免意外覆盖已有配置。MCP 重连操作保留在服务器连接管理中。

可用的可编辑模板：

| 模板 | 用途 |
| --- | --- |
| `build_android` | 执行一个 Android Gradle 任务，返回日志尾部、退出码及完整日志路径 |
| `build_rust` | 执行 `cargo build` 并保存完整日志 |
| `build_python` | 在当前工程构建 Python wheel 并保存完整日志 |
| `build_logs` | 查询当前容器、当前工作区最近完成的构建日志 |
| `git_status` | 查看 Git 工作区状态 |
| `git_diff` | 查看 Git 差异 |
| `git_log` | 查看 Git 提交记录 |
| `find_files` | 查找文件 |
| `rtk_command` | 在已安装 RTK 的环境中调用输出过滤命令 |
| `auggie_command` | 使用本人已安装并登录的 Auggie CLI 在指定项目执行任务 |
| `code_check` | 文件或目录的 Kotlin／Rust 词法和括号检查，Python 另做 AST 语法检查；不是编译或类型验证 |
| `code_symbols` | 提取文件或目录的限额符号列表 |
| `code_callers` | 按名称查询词法调用点候选，不是完整语义调用图 |
| `code_map` | 使用内置轻量工具查看 Kotlin、Rust、Python 的限额代码地图 |
| `codegraph_status` | 查询当前环境已经安装的 CodeGraph 状态，不安装、不建索引 |
| `codegraph_index` | 使用已安装的 CodeGraph 在当前工作区建立索引，会写文件并占用资源 |

**选择模板只填入新建编辑器；草稿可直接预览和手动试运行，但不写入命令列表、不注册为模型工具。只有明确保存后才持久化并注册**，不会自动启用一批工具或安装依赖。模板预设为关键词注入并带有相关关键词，不会默认每轮全部注入；保存前可以修改描述、参数、命令、关键词和注入方式，命令仍走现有执行器与授权链。

[RTK 官方说明](https://github.com/rtk-ai/rtk)介绍了 Git 状态、差异与日志、文件检索、测试输出过滤，以及回查原始输出的用法。过滤效果取决于具体命令和输出，不能保证固定的 token 节省比例。模板不会替你安装 RTK；未安装时会保留底层「找不到命令」错误，不会静默改跑其他命令。需要回查时按官方用法查看原始输出，不把过滤摘要当作完整证据。

### 使用已登录的 Auggie

先在当前容器或 SSH 环境自行安装 Auggie CLI，并用本人账号完成登录。在新建命令表单选择 `auggie_command`，填写项目目录 `path` 和任务 `instruction`；选择模板只填草稿，明确保存后才注册为模型工具，默认按关键词注入，超时为 600 秒。也可在草稿运行面板主动试运行。

模板采用官方[当前 CLI 参考](https://docs.augmentcode.com/cli/reference)和 [v0 CLI 参考](https://docs.augmentcode.com/cli/v0/reference)均支持的 `--print`、`--workspace-root`；任务内容作为标准输入上下文传入，命令位置使用固定提示，因此以 `-` 或 `@` 开头的任务不会被当作命令选项或附件引用。

Auggie 会使用已登录账号的服务，可能读取或修改项目文件、调用工具、建立索引并产生费用；实际操作受原 CLI 的权限与确认机制控制。它与 RTK 的输出过滤用途不同。模板不会自动安装、扫描凭据或添加跳过确认参数；未安装、未登录、权限拒绝等情况保留原始错误，不自动回退到别的服务。Android 容器中的真实 Auggie 兼容性与登录执行仍需在目标环境验证。

### 代码地图与可选代码图

本地环境随 App 提供轻量代码查询，不需要 Node 或另一个模型密钥。初始化容器后，可让 AI 查符号、代码地图或调用点候选，也可在终端执行：

```sh
aharou-code status
aharou-code symbols --path app/src --name Example
aharou-code map --path app/src --limit 80
aharou-code callers --path app/src --name example
```

AI 先按需发现代码结构工具，才展开其完整参数；展开状态按会话和工作区隔离，不会因为别的会话查过代码就常驻注入。较久未使用的会话可能需要重新发现。重启后也需重新发现。

这是一份**当前文件的限额结构快照，不是完整语义调用图**：Python 使用 AST，Kotlin/Rust 使用轻量结构提取；同名、重载、宏、反射、跨语言调用可能不完整，调用点只能作为候选。它不运行源码、不编译、不安装依赖；不能替代原搜索、编辑器诊断或构建验证。每次重新读取当前文件，不复用旧索引；结果带内容指纹，超过文件数、大小、扫描时间或输出限额时明确标记部分结果。优先指定子目录或符号，避免反复全仓扫描。小文件的结构元数据可能比原文更大；已知路径和相关行时直接读文件，不机械地先查地图。节省效果取决于任务，不能保证固定比例。

远程 SSH 主机不自动同步这些命令；未部署时保留原搜索、文件读取与诊断，不声称环境已就绪。

[CodeGraph](https://github.com/colbymchenry/codegraph) 是可选的独立工具，不捆绑进 APK，也不通过模板自动下载。先在目标环境按官方固定版本安装并验证兼容性，再保存状态或索引模板。安装、建立索引、连接 MCP 是三件不同的事；状态查询不能证明调用图完整。索引和第三方运行时可能占用较多资源，具体体积、Android 兼容性与节省效果尚未测量。

需要向 AI 提供图查询时，使用现有 MCP 页面导入以下配置，启动前检查工具已在 **MCP 实际执行的容器** 中安装；SSH 工作区的 stdio 后端与普通命令可能不同，详见 [MCP 服务器](./mcp)：

```json
{"mcpServers":{"codegraph":{"command":"codegraph","args":["serve","--mcp"]}}}
```

配置不包含密钥，不自动授权；第三方工具继续走 MCP 权限和按需发现。首次查询前确认目标仓库与索引状态，不把 CodeGraph 推荐的受影响测试列表当成完整 CI 的替代品。不要同时为同一工作区启动多个索引写入服务。

### Aharou 出包前的插件巡检

构建 Aharou 的 Debug、Beta 或正式 APK 时，打包前会自动执行受控插件巡检：通过真实 JavaScript 加载器、工具注册表和 HTTP/SSE 消费者检查加载、工具返回值、请求/事件挂钩、登录请求不受修改及卸载后撤销；同时复验权限入口与异常回退，再用已安装的 javac/D8 编译并检查 SDK 示例包。

这不是让模型回复一句“巡检通过”。缺用例、零用例、跳过、失败或旧报告均不能通过，缺编译器也会明确阻止出包，不会偷偷下载工具。巡检只运行仓库内的受控夹具，不扫描或执行用户安装的插件，不清理账户与凭据。

CI 保留 `plugin-patrol-evidence`，正式发布同时附带 `plugin-patrol.json` 报告，包含用例、原始 JUnit 摘要、源码摘要和示例包摘要。纯 JVM 巡检与 DEX 编译不证明 Android 真机 DEX 加载或原生 View 交互；这些项在报告中单列为未验证，不能读成“全平台全部通过”。

## 新建一个自定义工具

自定义工具 = **一段 JSON 参数表** + **一条 shell 命令模板**。模型调用时，App 把你的模板里的占位符换成模型给的参数值，在当前执行环境（本地容器或远程 SSH）里真实执行，输出直接回给模型。

填写顺序建议照下面来：

1. **名称**：模型按这个名字调用，只能用字母、数字、下划线、连字符，最长 64 位。创建后不能改名（改名等于换成一个新工具）。
2. **描述**：告诉模型「这工具做什么、什么时候用」。写得越具体，乱调越少。
3. **参数（JSON）**：一个对象数组，每项四个字段：

   ```json
   [
     {
       "name": "path",
       "type": "string",
       "description": "要统计行数的文件路径",
       "required": true
     }
   ]
   ```

   `type` 支持 `string` / `integer` / `number` / `boolean`；`required: true` 的参数模型不给就会被拦下并报「缺少必需参数」。面板里有「插入示例」按钮，点一下就有模板可以改。
4. **执行命令**：用 <code v-pre>{{参数名}}</code> 引用参数，例如：

   ```sh
   wc -l {{path}}
   ```

   执行前每个占位符都会被替换成 **shell 单引号转义** 后的参数值，所以参数里带空格、单引号、中文都不会把命令拆坏。参数值里的 <code v-pre>{{...}}</code> 也不会被二次展开。
5. **超时（秒）**：1~600，默认 60。超时会强制终止命令。
6. **注入方式 / 关键词**：见下一节。

### 命令模板的几条硬规则

为了避免「以为参数生效了、其实跑的是半条死命令」，下面这些情况会直接报错，不会执行：

- 命令里**一个占位符都没有** → 允许（固定命令，如 `df -h`）；只是参数一定不会生效，面板会提示你；
- 命令引用了**参数表里没声明的占位符**（例如把 <code v-pre>{{path}}</code> 打成 <code v-pre>{{pth}}</code>）→ 报错；
- **必需参数缺失**或全是空白 → 报错，模型会收到「缺少必需参数: xxx」并自己改正；
- 命令为空 → 报错。

可选参数不传时替换成空字符串 `''`，命令结构不会被破坏。

### 安全边界

自定义工具的每次调用**都要经过一次工具授权确认**（和你用 `Bash` 时一样）：确认框里的标题就是渲染后的完整命令，看一眼就知道模型要跑什么。授权弹窗支持「始终允许」，但被安全策略判定为敏感的调用仍会逐次确认。

换句话说：**能改命令模板的只有你自己**，模型只能往里填参数值，且参数值一律按字面量转义，没法靠参数把命令改成另一条。

## 注入方式：三种状态

每个工具单独设置，决定「这一轮是否允许被发现和使用」。普通工具不默认展开全部参数；主代理与成员从记忆库启用的工具目录选择名称，再按需发现真实参数。记忆与工具发现保留基础调用入口，但不会绕过关闭、关键词和角色限制。

| 状态 | 语义 |
| --- | --- |
| 按需发现 | 允许按需发现（默认）；发现后才展开参数 |
| 关键词发现 | 当前这轮**用户消息**（不含 AI 自己说过的话）命中任一关键词时才允许发现和调用 |
| 关闭 | 不进工具列表 |

关键词的匹配口径：

- **大小写不敏感**（`Deploy` 能命中 `deploy`）；
- **忽略空白**（关键词里的空格、换行都不参与匹配，`git log` 与 `gitlog` 等价）；
- **子串匹配**（用户消息里包含关键词就算命中，不需要整句相等）；
- **关键词为空时按「按需发现」处理**——避免你填了关键词模式却忘了写关键词，工具从此永远不出现。

关键词在输入框里用**逗号或空格分隔**，中英文逗号都认。

典型的用法：把「部署上线」「数据库迁移」这类不常用又敏感的自定义工具设成关键词注入，平时不占工具列表的位置，只有你真的提到它时模型才看得到。

## 条目存在哪

配置沿用仓库既有的「文件资产」范式（和自定义提示词、技能一致），一个工具一个文件，可以用文件管理器直接改、也能进版本库：

```
<配置根>/tools/custom/<名称>.json    一条自定义工具
<配置根>/tools/overrides.json        内置与 MCP 工具的描述 / 注入方式 / schema 说明覆盖
<工作区>/.aharou/tools/...           同结构，项目层
```

- **项目层优先、全局层兜底**：同名条目两层都有时，工作区里的那份生效。
- 有打开的工作区时，新建与修改写到该项目层；没有工作区时写全局层。
- 删除会把两层里的同名文件一起清掉，不会出现「删了又冒出来一条」。
- 单个文件写坏了（手改 JSON 出错）只影响那一条，其余工具照常工作，坏的那条会被跳过并记进日志。

## 出问题怎么办

| 现象 | 原因与处理 |
| --- | --- |
| 工具列表里看不到刚建的工具 | 检查注入方式是「关闭」还是关键词模式但关键词没命中当前这句话 |
| 模型从不调用某个自定义工具 | 描述太笼统，模型不知道什么时候该用；把「什么时候用」写进描述 |
| 调用时报「缺少必需参数」 | 参数标了 `required`，但模型没给值；可以把它改成可选，或在描述里写清格式 |
| 调用时报「占位符未声明」 | 命令里的 <code v-pre>{{x}}</code> 和参数表里的 `name` 对不上 |
| 保存失败 | 名称不合法（只能是字母数字下划线连字符）、参数 JSON 不是数组、执行命令为空——面板会就地标红 |
| 内置或 MCP 工具的 schema 不能保存 | 检查 JSON 是否有效，是否改动了参数名、类型、必填项、枚举等结构；只保留说明元数据改动，或重置为原始 schema |
| 更新后 schema 说明没有应用 | 原始参数结构可能已变化；对照新的原始 schema 重新编辑，不要复制旧的参数结构 |
| RTK 模板提示找不到命令 | 当前执行环境未安装 RTK；模板不自动安装，也不自动切换命令 |

## 离线逆向与安全审计

### 安装离线分析环境

在 App 容器终端运行 `aicode`，进入「环境安装」，选择「授权离线逆向分析」。确认清单后，只补装缺少的 `readelf`、`objdump`、`strings`、`file`、Java 和 Python 3；`jadx`、`apktool` 分别询问，默认跳过。工具已可用时不会重复安装，不默认安装 Ghidra，也不更换容器镜像。

该场景使用当前容器的 apk、apt、dnf、yum、pacman 或 xbps 软件源，按当前架构查询包后再安装，适用于 ARM64。安装过程需要访问软件源；「离线」指后续对已授权样本的分析，不代表安装无需联网。仓库、架构缺包或查询失败会明确显示「不可用」并返回失败，不会悄悄添加第三方软件源或下载反编译器压缩包；安装命令成功但所需工具仍找不到，也不会报告就绪。未选择的可选工具会保留「不可用（未安装）」状态。

安装场景只配置工具，不读取、解压或执行用户样本；自动探测也只查找命令，不启动分析工具。SSH 主机须在其自身环境准备这些命令，本地容器装好不代表远程主机可用。

### 使用内置审计技能

可让 agent 加载内置 `security-audit` 技能，对你明确授权的本地文件做静态检视。它提供文件 SHA-256、字节熵、ELF/DEX 头字段、PE 的 COFF 时间戳、入口 RVA 与 ImageBase、ZIP/APK 目录统计，以及 Flutter/React Native/UniApp 的未验证路径线索；另提供 SQL、XSS、CSRF、SSRF、命令、路径、XML、隐私、权限和自启动等源码复核线索。这些是静态分诊线索，不是鉴定或安全结论。不会联网扫描、执行样本、解压归档、读取凭据，也不会安装反编译器或改变现有工具权限。

本地初始化会将配套资源放到 `~/.aharou/builtin-skills/security-audit/`，脚本为 `scripts/audit.py`；先确认文件已出现再按技能命令运行。SSH 工作区在加载内置技能前，将配套文件同步到工作区绑定主机的 home 下 `.aharou/builtin-skills/`，不写入自定义技能目录；连接变化或同步失败会返回明确错误，不会假装已部署或扫描。工具发现只检查可用命令，不执行它们。APK 候选不是签名验证或清单解码，正则命中不是已证实漏洞，零命中也不是安全证明；超限、截断与未覆盖内容都会单列。

安全术语按真实分析意图合并，不用换名来绕过授权。上游适配只记录边界：DSH 的 MIT/宿主依赖不代表可以盲装；VCP 的 CC BY-NC-SA 代码不复制进 GPLv3 项目；Windows 专用且许可证未知的 skill 不导入 Android。DSH 与 VCP 的公开许可证已核对；Windows 项目的独立许可未确认。没有复制上游代码，本工具包为原创实现。

## 会话过程读取

助手可以列出、搜索并读取当前工作区的主会话与成员会话。过程只包含已保存的正文、提供商已返回并保存的思考文本、工具调用与结果，不包含未提供的内部推理、加密思考块或签名。跨工作区仍拒绝，运行中的上下文构成仍仅当前会话可查看。

过程从新到旧分页；一页读完后继续下一页。单条字段超过长度上限时，按返回的续读位置继续读取该条消息。新消息可能改变分页位置，读取期间应核对消息标识。

## Session observability

`sessions` adds `action=tool_calls` for redacted persisted tool receipts in a session belonging to the current workspace. Supply `session_id` (defaults to the current session), optional exact `tool`, `status` (`SUCCESS`, `ERROR`, `PARTIAL`), inclusive epoch-millisecond `after` / `before`, `limit` (up to 200) and nonnegative `offset`. Results include `nextOffset`; `null` means the final page. Newest-first offset pagination is live, so concurrent new calls may shift pages. Receipts are retained for the existing 30-day window; they are not a complete permanent audit history. Denied calls have an empty status and remain visible without a status filter. Full output and build-authorization bodies are not returned by this action.

`action=context` returns the latest in-process final workflow request composition for the current session only, after stored-tool folding and privacy masking, subject to the same workspace ownership check as session reading. An explicit ID for another session is rejected even within the same workspace. It returns counts and fixed section identifiers, never prompt headings or injected bodies. Estimated tokens are a local character heuristic, not provider usage. Workspace boundaries remain enforced for both actions.

## Project controls

Project tasks open in map view. The overflow menu includes start/stop, tree/map, search, fit, and conversation actions. Delete removes project/task records only; stop running work first. Workspace files and conversations are retained.

工具目录为空查询时只按 `offset` 分页返回名称和描述，不会自动激活；准确完整工具名优先只展开该项，以用途关键词查询时按空格分词且每个词都须命中，之后才激活选中工具的参数。严格工具白名单成员仍有只读发现和本工作区过程查询入口，显式黑名单、关闭和关键词策略优先。目录在默认原生记忆中显示有界摘要和完整目录入口，不因工具数量超过单条记忆预算而失去入口。


### DSH 目录网络通道

错误会区分域名解析、TLS握手、超时、HTTP状态、公开目录解析和来源下载，不再将所有问题统称目录格式变化。宿主TLS连接关闭时，可以使用当前已就绪容器内已有curl读取同一公开目录；不会安装rootfs或工具，不关闭证书验证，也不会在HTTP403/429拒绝后自动换通道。界面标明实际使用的目录通道。备用只负责目录，文件下载及原生安装仍分别报告真实结果；任意DSH专用运行时不因此获得兼容性。


## 实时上下文脚本

在工具页顶栏「＋」打开脚本编辑器，开启「实时上下文脚本」后保存。已有脚本也可编辑切换；默认仍为普通工具脚本，只有模型调用时才执行。实时类型不注册为函数工具，也不是工具说明的「每轮注入」选项。

每次主会话或成员会话的模型请求构建时，实时脚本接收当前会话、工作区、用户输入及消息历史组成的标准输入 JSON。保存的命令经已有命令工具与同一权限流程执行；启用不是永久授权，角色不允许命令工具时不会执行。默认限时 10 秒、输出 8192 字符，可在编辑器调整到 1–1800 秒、1–65536 字符。输出注明用户脚本来源，按数据而非可信指令放在请求历史末尾，避免实时变化改写系统提示前缀；当次结果替换上次结果，不写入持久对话，也不在不同会话间缓存。可信宿主插件若明确改写整份提示，仍保留其原有改写语义。

拒绝授权、超时或执行异常会留下诊断并继续原请求；非零或未知退出、引擎截断或超过脚本输出上限的结果不注入。用户停止会撤下本会话待批并取消实时执行，发起模型前再次检查停止；普通命令的软停止策略不变。停用后后续请求不调用脚本。命令仍在实际工作区执行，可能有真实副作用，不应把实时脚本当成沙箱。

## 可信宿主插件的上下文与反射

JS 和 DEX 插件共用 SDK 的上下文回调：每次正式会话请求注入前取得当前提示与会话元数据，默认透传；插件可以返回修改后的当前提示。无效返回或异常记录诊断并保留输入，不会自动停用插件。该接口在模型请求序列化之前消费，不替代原有 HTTP/逐帧 SSE hook，也不修改登录或鉴权。

JS 可通过 `host.reflect(operation, arguments)` 使用与 DEX 的 `host.call("reflect." + operation, JSON文本)` 相同的宿主对象能力。`context` 取得 Application Context 句柄，`class` 按名称取得类句柄，`new` 构造对象，`invoke` 调用方法，`get/set` 读写字段，`release` 释放单个句柄。方法与构造参数显式提供类型名称和参数数组；目标对象以返回的句柄传递。宿主自有对象的 private 成员允许反射；每个插件运行代拥有独立句柄，不能引用其它插件句柄，卸载清理后旧句柄失效。

这是用户主动信任、与宿主同 UID 的原生扩展，不是安全沙箱，不需要 Root。Android UID、系统 hidden API、Manifest 权限与设备 DEX 限制仍适用；反射可改对象字段及调用逻辑，不等于能替换任意已加载 DEX 方法体。工具调用仍走原有权限流程。动态编译不自动安装或下载编译器，失败保留旧可用版本。源码实现及 JVM 夹具不证明手机端 DEX、JNI 或原生 View 已验证。


## 浏览器异步脚本结果

浏览器执行异步 JavaScript 时，每次调用使用独立的随机请求标识；超时或取消后的迟到成功、失败回调不会成为下一次调用的结果。执行脚本仍等待最多 30 秒，浏览器异步抓取仍等待最多 60 秒；超时或取消不会撤销网页中已经发生的操作，也不会自动重试脚本。
