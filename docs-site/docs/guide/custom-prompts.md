# 自定义提示词

Aharou 的系统提示词可以自己改。默认提示词随 App 内置、升级时自动更新；你只要把想改或想加的片段放进自定义目录就能覆盖或扩展，不用动 App 本体。

::: tip v1.12.0 起
本文的片段命名规则（`<两位数字>-<名称>.md`）、按数字新增片段、`.no-builtin` 完全禁用开关与 <span v-pre>`{{AICODE_*}}`</span> 变量自 **v1.12.0** 起支持。更早的版本只能放与默认片段**完全同名**的文件来覆盖，不支持按数字新增、`.no-builtin` 与变量。
:::

## 目录结构

提示词放在 AI 配置目录 `~/.aharou/` 下（容器内路径是 `/root/.aharou/`）：

```
~/.aharou/
├── prompts/          默认提示词（App 启动时全量释放，升级自动覆盖）
│   ├── 00-identity.md
│   ├── 10-communication.md
│   ├── ...           顶层是「静态基线」片段，按两位数字前缀排序
│   └── agent/        按需注入的片段（不进静态基线，用到时才读取）
│       ├── plan-mode.md           PLAN 模式提醒
│       ├── auto-mode.md           AUTO 模式提醒
│       ├── subagent-base.md       子代理基础运行规范
│       ├── compact-summary.md     长对话上下文压缩
│       ├── title-generator.md     会话标题生成
│       ├── commit-generator.md    Git 提交信息生成（Git 页的「AI 生成」）
│       └── init.md                /init 命令的指令正文
├── prompts.custom/   你的自定义片段（覆盖或新增，升级不动这里）
│   ├── 50-我的安全规则.md
│   ├── 25-额外要求.md
│   └── agent/
│       └── plan-mode.md           覆盖按需片段
├── skills/
└── docs/
```

片段分两类，命名规则不同：

- **静态基线**（`prompts/` 顶层）：`<两位数字>-<名称>.md`，数字是它的身份，决定在系统提示词里的位置。
- **按需片段**（`prompts/agent/`）：没有数字，用到时才读取（如切换模式、压缩上下文、派发子代理、生成标题）。

## 命名规则

自定义片段放在 `prompts.custom/`：

- **顶层文件**必须是 `<两位数字>-<名称>.md`（如 `05-开头.md`、`50-我的安全规则.md`）。数字即身份：
  - 数字与某个内置静态基线片段相同（内置数字为 `00`、`10`、`15`、`20`、`30`、`40`、`50`、`60`、`70`）→ **覆盖**该片段，尾部名称可随便取；
  - 数字不在上述集合里 → 作为**新增片段**，按数字大小插入基线的对应位置（如 `05-开头.md` 排在 `00` 与 `10` 之间）。
- 不符合该格式的文件（如 `notes.md`、`2024-备忘.md`）会被忽略。
- 同一数字有多个文件时只取文件名排最前的那个，其余忽略——请保持数字唯一。
- **`agent/` 子目录**里的片段没有数字身份，按**精确同名**覆盖（如 `prompts.custom/agent/plan-mode.md`）。

## 加载优先级

每个片段按这个顺序查找，找到就用，不再往后找：

1. 自定义版本：顶层数字片段按数字身份（`prompts.custom/` 顶层）、其余按同名（`prompts.custom/agent/xxx.md`）
2. `~/.aharou/prompts/<同名文件>` — 本地默认副本
3. App 内置的版本 — 兜底

所以你只需要放想改或想加的那几个片段，其余会自动用默认版本。

## 怎么改

1. 在 `~/.aharou/prompts.custom/` 下（没有就手动创建）放入片段：覆盖内置片段用相同数字命名，新增片段用尚未占用的数字命名，子目录片段（如 `agent/plan-mode.md`）对应放到 `prompts.custom/agent/` 下。
2. 编辑内容。
3. 数字片段在下一次构建请求时重新读取；已经发出的请求不受影响。按需片段在对应场景下读取。

编辑方式有三种：在终端里用 `vi` / `nano` 直接改；让 AI 帮你写（它的文件工具能直接读写这个目录）；或者[用文件管理器访问 App 私有目录](/guide/files#工作区文件在手机上的位置)。

## 单独关闭某个片段

不想用某条内置片段时不必整体禁用：设置 → 提示词页每行右侧都有开关，关掉即不再注入，内置片段、本地副本、自定义片段一视同仁。

- 关掉的片段仍留在列表里（开关显示为关），随时可以重新打开；
- 标记落在 `~/.aharou/prompts.custom/.disabled/<两位数字>`（如 `.disabled/60`），存在即关闭；删掉文件就恢复注入；
- 想看注入内容时不受影响：关掉的片段在详情页照常可读、可编辑；
- 项目层 `.aharou/prompts.custom/.disabled/60` 里的标记同样生效，只对该工作区关闭；App 里的开关统一写在全局层。

### 按需片段也能单条开关和改

配置 → 规则页的「运行时规则」列出按场景读取的内容，并显示触发依据：`plan-mode` / `auto-mode`（切模式时的提醒）、`subagent-base`（子代理基线）、`memory-discipline`、`stuck-nudge`、`workspace-android` / `workspace-rust` / `workspace-python`（识别到工程类型时注入的规约，同一工作区命中多种类型会依次全部注入）。

- 右侧开关同样是存在即关闭，标记落在 `.disabled/<文件名>`（如 `.disabled/plan-mode.md`）；
- 点行会在底栏里改正文，保存写到 `prompts.custom/agent/<同名>`（有工作区写项目层，否则写全局层）；
- 起标题、压缩上下文、记忆整理这些内部一次性提示词没有给开关（关掉只会让对应功能惄惄退化），需要改就自己放 `prompts.custom/agent/<同名>` 覆盖。

## 数字片段的注入方式

在提示词编辑页可以分别启停默认注入、关键词注入和成员注入。默认注入适用于主会话以及继承主规则的成员；关键词匹配当前请求；成员注入可同时选择多个成员。任一条件命中即可注入，同一片段不会因多条件命中而重复追加。关闭关键词或成员注入会保留已填写的关键词和成员选择；片段行开关仍是总开关。

团队保存阶段与交接要求，成员保存职责和证据标准，技能保存专项流程，规则保存行为约束，记忆保存事实与偏好，通用提示词保存跨任务执行约定。同一段细则只在一个来源维护，其他入口说明何时读取，避免同时注入多份相互矛盾的正文。模式和项目类型等运行时规则显示条件触发依据，不作为普通关键词片段。

技能名称、关键词或清单出现在上下文中，不代表技能正文与附属审计清单已经加载；保存文件或更新 APK 资源，也不代表当前会话已经采用新内容。默认指引要求分别报告内容保存、静态检查和实际加载结果。内置成员与团队只在同名文件不存在时补发，升级不会覆盖已经落盘或编辑过的同名定义；保留副本需要按新默认内容手动核对，不要为更新文案删除用户修改。

## 完全禁用内置提示词

::: tip 先考虑单片段开关
只想停掉一两条内置片段时，用上面的单片段开关；`.no-builtin` 排除所有非自定义的数字片段，自定义数字片段仍受各自的开关和注入条件控制。这不是关闭全部系统上下文的开关。
:::

在全局 `prompts.custom/` 下新建一个名为 `.no-builtin` 的文件（内容随意），重启 App 后，数字片段基线只保留自定义内容。当前加载器在主会话与成员路径中共用这个过滤条件：

- 不再注入内置数字片段；技能清单、成员索引、记忆、项目规则、工作区与时间仍按动态区块开关追加；
- 自定义片段可使用下面的变量；已展开的动态内容不会重复追加；
- 成员继承主规则或命中成员注入条件时，同样不会取得被排除的内置数字片段；成员自身角色正文、基础片段与场景片段走各自的加载路径，不因本开关一并停用；
- 没有可识别片段或本轮关键词均未命中时，静态部分为空，但不会清空动态上下文。

::: danger 这是"完全接管"
内置数字基线被排除后，请在自定义片段中保留必要的身份、工具说明与安全边界。动态项目规则和成员角色仍可能生效，不能把本开关当成清空全部约束或增加工具权限。
:::

## 可用变量

在片段正文里写这些占位符，运行时会替换成真实内容；清单为空时替换为空字符串：

::: v-pre
| 变量 | 替换为 |
| --- | --- |
| <code v-pre>{{AICODE_SKILLS}}</code> | 可用技能清单（名称 + 描述） |
| <code v-pre>{{AICODE_MEMORY}}</code> | 记忆摘要清单（全局 + 项目） |
| <code v-pre>{{AICODE_SUBAGENTS}}</code> | 可用子代理部门索引（部门 + 角色数 + 代表角色，选角走部门 + 关键词） |
| <code v-pre>{{AICODE_PROJECT_RULES}}</code> | 项目规则（`AGENTS.md` / `CLAUDE.md`） |
| <code v-pre>{{AICODE_WORKSPACE}}</code> | 工作区上下文（当前项目根目录） |
| <code v-pre>{{AICODE_DATE}}</code> | 当前日期（`yyyy-MM-dd`） |
:::

::: tip 写了变量就不会再自动追加
平时系统会把技能/记忆等自动附在提示词末尾；只要你的片段里写了对应变量，该内容就**只在变量处插入一次**，不会再自动追加，避免重复。未写的仍照常自动追加。
:::

其它占位符（如压缩提示词用的 <span v-pre>`{{INSTRUCTION}}`</span>）不受影响。

## 按需规则（rules）

低频、专门的规则不必常驻系统提示词。把它们放进 `~/.aharou/rules/<名称>.md`，App 只在系统提示里注入「名称 + 摘要」清单，AI 判断某条规则与当前任务对口时用 `loadRule` 取完整正文再照做。

- 文件首行的 `<!-- ... -->` 注释就是清单里显示的摘要，正文写规则内容；
- 文件名（不含 `.md`）就是规则名称；
- 同名文件覆盖内置版本（内置规则随 App 打包，位于 `assets/rules/`）；删掉自定义文件即恢复内置版本。
- 规则页下方有「内置按需规则」分组：每条一个开关（关掉即不进清单，`loadRule` 也取不到），点行可在底栏改正文，保存写到 `~/.aharou/rules/<同名>.md`；关掉的标记存在 `~/.aharou/rules/.disabled/`。

## 动态注入区块

系统提示词末尾会按固定顺序追加若干动态内容（技能清单、子代理索引、团队、记忆索引、项目规则、按需规则清单、工作区上下文、工程类型规约、模型身份、共享区信箱、当前时间、工作区切换提醒、人格与核心档案）。这些区块沿用独立的文件开关；提示词页不再重复显示动态区块开关列表。

- 关掉某块后，本轮就不取该内容也不再追加；片段里写了对应的 <code v-pre>{{AICODE_*}}</code> 变量时同样展开为空，不会抢救回来；
- 标记落在 `~/.aharou/prompts.custom/.disabled-blocks/<key>`（如 `.disabled-blocks/skills`），存在即关；
- 关掉技能清单 / 子代理索引后再用手写片段写工具说明时，AI 就看不到哪些技能可用，需要自己补；
- 这些区块开关与「完全禁用内置提示词」不冲突：`no-builtin` 管静态片段，区块开关管末尾的动态段落（两者同时生效）。

## 升级时的行为

- `prompts/` 目录每次启动都会被内置版本全量覆盖，所以默认提示词会随 App 升级自动更新。
- `prompts.custom/` 目录 App 永远不会自动写入或删除，你的自定义在升级后完整保留。

::: danger 请勿直接修改 prompts/ 目录
`prompts/` 目录中的内容在每次启动时都会被全量重置，手动修改的内容在 App 升级或重启后会被覆盖。如需持久自定义，请务必保存在 `prompts.custom/` 目录中。
:::

## 恢复默认

删掉 `~/.aharou/prompts.custom/` 下对应的文件，那个片段就恢复默认版本；删掉整个 `prompts.custom/` 目录则全部恢复（`.no-builtin` 一并删除后内置提示词重新启用）。

## 注意

- 旧版把 `80-plan-mode.md`、`81-auto-mode.md`、`90-subagent-base.md` 放在 `prompts/` 顶层，**v1.12.0 起**已移到 `prompts/agent/` 且去掉编号；对应的自定义覆盖请改用 `prompts.custom/agent/plan-mode.md` 等路径。
- `60-tools-and-paths.md` 这类片段会随工具变更而更新。如果你覆盖了它，App 升级后不会自动获得新版工具说明，AI 看到的工具定义可能和实际不一致。需要更新时手动同步一下，或者删掉你的自定义版本让默认版本重新生效。
片段注入策略也可通过 `config` 的 `prompt_fragments` 集合读写：每个两位编号下提供 `default_injection`、`keywords_enabled`、`members_enabled`、`keywords` 和 `members`。关键词与成员名每行一项，修改列表不会自动打开开关。

## 规则、记忆与提示词如何分工

这三项都能使用 Markdown，但不建议合并成一个记忆库：

| 类型 | 保存什么 | 默认使用方式 |
| --- | --- | --- |
| 规则 | 稳定约束、项目边界与验收要求 | 主规则及 rules.d 常驻，专项规则按需加载 |
| 记忆 | 可更新的事实、偏好、经验 | 相关条目召回，正文按需读取；核心档案可常驻 |
| 提示词 | 角色、工作流程、输出格式 | 按默认、关键词或指定成员条件注入 |
| 技能 | 专项方法与配套资源 | 先提供名称和简介，需要时加载正文 |
| 知识库 | 参考资料和可引用证据 | 任务需要时检索，不整库塞进对话 |

同一条信息只维护一个权威来源，用引用连接其他位置，不自动把旧配置迁移或删掉。基础提示只保留执行约定与读取入口，低频工具细则改为按需规则，事实交给记忆，资料交给知识库。现有开关和用户覆盖仍然有效，不自动关闭你的片段。

文件拆成几类本身不决定 token 用量，关键是本轮实际加载了多少正文：项目主规则及其片段会注入，按需规则通常只提供目录摘要；记忆注入受类型、召回和预算控制。把所有文件并成一份常驻提示，反而会把原本不必读取的内容带入每一轮。应合并重复话术，而不是合并所有存储。

同一次组装内，相同技能、记忆、成员索引、项目规则或按需规则占位块只在第一处展开；工作区和日期仍可重复，未知标记不改写，插入的动态正文不再次按模板解释。不同来源或作用域即使同文也不会被模糊删除。默认工具手册与记忆纪律已精简，但用户旧覆盖不会自动变成新默认；更新后请在提示词设置对比实际生效内容。

资源字节数、应用估算的 token 与模型 API 返回的实际计费用量是不同指标。判断优化效果应对比相同任务、模型、工具及配置，不能仅凭文件变小就宣称费用或速度按同一比例改善。

提示词编辑页的默认、关键词、成员三个条件是“或”的关系；如果希望只在关键词或指定成员命中时生效，必须关闭默认注入。同一片段即使命中多个条件也只加入一次。
