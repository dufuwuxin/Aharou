# 容器与镜像

Aharou 里 AI 执行命令的地方叫「容器」。入口在「设置 → 容器与镜像」，列表是单选的，选中哪个，AI 的命令、文件读写和终端就都在哪里执行。

本地运行仅接受原生 ARM64 rootfs，不支持 Alpine、x86/AMD64 或 32 位 ARM，不使用 QEMU、Box64、FEX 等跨指令集转译。既有 PRoot 用于容器路径隔离，不是指令集转译；使用原生架构也不保证任意工具或构建任务都能兼容或达到某个速度。

应用仅支持 Android 8.0+ 的 ARMv8（64 位 `arm64-v8a`）设备，安装包与内置/在线镜像只提供 ARM64 版本；不再提供 x86、x86-64 或 32 位 ARM 安装包。此限制不影响连接其他架构的远程 SSH 服务器。

后端分两类：**本地容器**（在手机上跑一个 Linux 系统）和**远程 SSH**（在你的服务器上跑），两者必选其一。远程模式见[远程 SSH 模式](/guide/remote-ssh)。

## 容器列表

每一行是一个容器配置，名称后面有来源标记：内置、自定义、SSH，颜色区分；当前默认容器还会多一个「默认」徽章，在编辑弹窗里可以「设为默认容器」（只给本地容器）——默认容器是远程工作区模式下本地 MCP 等服务运行的地方，默认是内置 Ubuntu。

以下操作对所有容器一致：

- **排序**：长按行的名称区域上下拖动可调整顺序（重启后保持）；新添加的容器排在列表最前。
- **编辑**：行尾的铅笔图标。
- **重置**：编辑弹窗右上角的刷新图标。这是破坏性操作，会删掉容器里已装的工具和配置，需要二次确认；和切换容器一样，确认后正在运行的 AI 会话和所有终端标签都会关闭。装了很多东西的大容器删起来要几十秒，期间会弹出「正在清理容器数据」并实时显示已清理的项数，删完自动关闭，界面不会卡住。
- **删除**：行上左滑露出红色删除按钮。删本地镜像会一并清理它的 rootfs 释放空间（同样显示清理进度）；删远程 SSH 只删配置，不动服务器上的数据。

内置 Ubuntu 也可以删。删光了列表会显示空态，上面有个按钮一键恢复内置 Ubuntu，所以不用担心删错。

容器运行起来后，App 会自动识别里面装的是什么系统，在列表左侧显示对应的系统图标（例如 Ubuntu、Debian、CentOS），识别不出来就显示默认图标。

## 开发容器怎么选

采用「一个 App、多套独立容器、开发工具按需安装」，不把不同发行版的包管理器混进同一套系统。每套容器保留自己的软件仓库与包数据库，工作区按需要绑定容器。

| 用途 | 建议系统 | 取舍 |
| --- | --- | --- |
| 离线起步与通用开发基线 | 内置 Ubuntu 24.04 LTS ARM64 | 随 App 提供官方 Ubuntu Base；使用 glibc，开发工具按需安装，仍须选择原生 ARM64 工具 |
| Android / JVM、Python 原生扩展、综合开发 | Debian / Ubuntu | 作为主开发环境优先考虑，仍需确认 ARM64 工具是否可用；切换发行版不等于解决所有二进制兼容问题 |
| 需要 pacman、较新开发软件包 | Arch Linux ARM 精简版 | 已在在线镜像列表提供；滚动更新，应保持整套系统一致更新，避免仅更新索引后局部升级 |
| 需要 XBPS 的独立开发环境 | Void aarch64 glibc | 官方 ROOTFS 已接入镜像同步；在线条目仅在官方校验和验证、上传完成后发布，未出现时仍可手动导入。面向 glibc 工具时不要选 musl 变体 |
| 已使用 Manjaro ARM 的项目 | Manjaro ARM 精简版 | 已在在线镜像列表提供；作为可选环境，不再额外混入 Arch 软件源 |

Arch / Manjaro 的精简流程去掉容器不使用的启动文件、内核模块、固件、文档和多语言资源，保留原发行版包管理器。开发运行时从环境菜单按场景安装，不预装所有 SDK，也不删除包数据库、证书、动态库或软件包签名钥匙串。

旧内置 Alpine 会升级为内置 Ubuntu，具体数据保留规则见下节；用户自行导入的镜像不会被批量删除，但 Alpine 与非 ARM64 本地镜像将拒绝安装和启动。请导入受支持的 ARM64 rootfs。这里是选型建议，不代表所有发行版都已完成当前手机上的性能或编译验收。

## 内置 Ubuntu 容器

App 自带官方 Ubuntu Base 24.04.5（24.04 LTS）ARM64 镜像，首次启动会自动加进列表并选中。打包前核对官方 SHA256SUMS、实际文件哈希、系统版本与原生 ARM64 shell，不执行镜像内程序。

::: tip 首次使用请先进终端完成初始化
本地容器的环境准备（解压 rootfs 及基础工具安装）在首次进入**终端页面**时自动触发。请在初次使用时先进入终端页完成初始化，之后 AI 的命令执行、Git 管理与本地 MCP 即可正常使用。
:::

::: info 旧内置 Alpine 的升级
升级会先在独立目录准备并验证 Ubuntu，再保留旧容器的 `/root` 与 `/home` 用户数据。旧系统目录和已安装的软件包不会复制到 Ubuntu，工具与软件源应按 Ubuntu 重新安装配置。只有新环境验证和用户数据迁移成功后才移除旧内置目录；失败保留旧数据，并提示错误，不会回退启动 Alpine。

工作区项目、全局 AI 配置和共享目录不在此次迁移清理范围。旧 `/root` 下与挂载点同名的真实文件或链接，会保存在新环境 `/root/.container-migration/` 内，按旧环境目录名称分组；名称已占用时使用带编号的新目录，不覆盖已有内容。迁移不会沿这些链接写入外部目录。迁移过程中请保留足够空间容纳新旧两份系统；遇到错误请先处理空间或镜像校验问题后重试，不要手动删除旧用户数据。

用户自行导入的 Alpine 镜像不会被自动批量删除，但已不支持启动；请先备份其中的个人文件，再改用原生 ARM64 镜像。日后主动点**重置**仍会清除该容器的系统和容器内数据，请事先备份。
:::

## 首次进终端的初始化菜单

不管是内置 Ubuntu 还是你自己导入的镜像，rootfs 解压完成后第一次进终端都会弹出一个菜单，四个选项：

**1. 自动安装依赖（推荐）**

先选软件源、更新软件包索引，再列出要装的东西（bash、curl、ripgrep、git 这些基础工具，加 Node.js 和 Python 3），输入 `y` 确认后开始装。

**2. 环境安装**

打开「环境安装」菜单，按场景选择要装的开发环境（见下一节）。场景是一组运行时的组合，选完确认清单即可安装；菜单里也有「自定义安装」可以逐项勾选、指定主版本。

**3. 手动安装（不再提示）**

跳过安装，之后进终端不再弹这个菜单，工具你自己装。想让菜单回来就重置容器。

**4. 退出**

这次不装，下次进终端还会问。

装包失败不会影响你进入 shell，重进终端可以再试一次。

### 软件源选择

换源时可以选：

- `1) 自动探测（推荐）`：实测各个镜像源在当前包管理器下的真实可达性，自动跳过失效或被墙的源。
- `2~6)` 指定某个镜像源：华为云、清华 tuna、中科大 ustc、腾讯云、阿里云。Void 只列提供 Void 仓库的清华 tuna、北外 bfsu、南大 nju（序号 2~4），换源写入 `/etc/xbps.d` 覆盖文件，仍校验官方签名。
- `0)` 不换源，保持默认。

换源前会备份原配置，失败自动恢复，不影响后续安装。内置 Ubuntu 的 rootfs 保持 Ubuntu 官方源，需要国内源就在这个菜单里换。Void 为滚动发行，装包前会先单独更新 xbps，再升级已装软件包，安装清单里会写明。

## 解压完还会试启动一次

rootfs 解压结束、在把容器标成「已安装」之前，App 会自己验一遍：关键目录在不在（`/bin/sh`、`/etc/os-release` 这类），再真的在容器里跑一条最短的命令。两道都要过：

- 任何一步不过，**不会把容器标成已安装**，而是直接告诉你原因：缺哪些关键目录、启动时报什么错、或者等了 60 秒还没起来（镜像不完整，或设备当时负载太高）。
- 没过就重试或换一个镜像；因为没落标记，下次进终端会重新解压安装。

这样装坏了会当场报错，而不是留下一个「看着装好了、之后每条命令都莫名失败」的容器。

## 联网用的 DNS

容器里的下载、克隆、装包都靠 `resolv.conf` 里的解析地址。默认**跟着手机走**：每次启动容器前，App 会把手机**当前网络**下发的 DNS 同步进去——换 WiFi、插拔 SIM、开或关 VPN 之后，下一次命令用的就是新网络的 DNS（VPN 下发内网 DNS 时，容器里也能解析那些内网域名）。内容没变就不动文件。

想固定用公共 DNS，去「设置 → 容器与镜像」顶部那行「镜像与 DNS」：

- **跟随系统**（默认）：用手机当前网络的 DNS，换网络后自动更新。
- **Cloudflare + Google**：1.1.1.1 / 1.0.0.1 / 8.8.8.8，海外解析更稳。
- **阿里 + DNSPod**：223.5.5.5 / 223.6.6.6 / 119.29.29.29，国内解析更快。

选完立即写进容器，不用重装；容器被重置或换镜像后会重新应用。同一页上面还能在「官方源 / 国内镜像」之间一键切软件源，写入失败的具体原因就显示在这一页上。

## 随时安装开发依赖（aicode）

初始化菜单只会在首次进终端时弹一次。之后想再装别的运行时（比如后来才需要 Java 或 Go），有两个入口，打开的都是同一个「环境安装」菜单：

- 在终端里执行命令 `aicode`；
- 点终端右上角的**工具**图标，选「重新运行环境安装」，会在一个新标签里打开同样的工具。

`aicode` 提供按场景安装，选一个场景、确认清单即可：

| 场景 | 安装内容 |
| --- | --- |
| 通用开发 | 基础工具 + Node.js + Python 3 |
| Python 开发 | 基础工具 + Python 3 + pip |
| Node.js / 前端开发 | 基础工具 + Node.js + npm |
| Kotlin / Android 开发 | 基础工具 + JDK 17 + Android SDK |
| Flutter 开发 | 基础工具 + JDK + Android SDK + Flutter SDK |
| Java 开发 | 基础工具 + JDK |
| Go 开发 | 基础工具 + Go |
| Rust 开发 | 基础工具 + rustc + cargo |
| PHP 开发 | 基础工具 + PHP + Composer |
| 仅基础工具 | bash、curl、ripgrep、git |

基础工具（bash、curl、ripgrep、git）任何场景都会一起装上。场景默认装软件仓库里的最新主版本；要指定版本，用菜单里的「自定义安装」逐项勾选。菜单里还能单独换软件源、查看已装了哪些运行时。

「Kotlin / Android 开发」「Flutter 开发」是重场景，需要下载 JDK、Android SDK 或 Flutter SDK，耗时较长、占用较多存储。请使用原生 ARM64 工具链；aapt2、adb、NDK 等组件也必须支持 ARM64，只有 x86/AMD64 二进制的构建链不能通过转译补齐，可能无法在本地构建。装好后新开终端可使用 `JAVA_HOME`、`ANDROID_HOME` 等环境变量。具体步骤见进阶教程，但旧教程中的跨架构转译做法不适用于当前本地容器。

终端右上角原来的设置图标已改为**工具**图标，点开后在面板里除了环境工具入口，还能调整配色主题、字号、字体和光标样式。

## 编译时的内存上限（Gradle 堆）

「设置 → 容器与镜像」里的**Gradle 堆内存上限**滑条，决定容器里编译 Android / Kotlin 工程时 JVM 最多能占多少内存。范围 2～8 GB，默认按设备内存推荐一档，改完**下一次编译生效**。

- **对所有工程生效**：这个值写进容器用户级的 Gradle 配置，优先级高于工程里写死的 `org.gradle.jvmargs`，不用每个项目改一遍。
- **调低了不等于跑不动**：这是上限，不是预占。上限比实际可用内存大时，JVM 会迟迟不回收、一路把内存堆满，最后被系统直接杀掉——表现就是编译跑到一半悄无声息地中断，日志停在编译任务上、没有任何报错。把上限压在可用内存之内，反而能稳定跑完。
- **调高了更快，但有风险**：机器内存宽裕（后台应用少）时可以往上调，编译少几次垃圾回收会快一些；调太高则会重新碰到上面那种中途被杀。
- **并行编译也吃内存**：一次编多个 flavor 时几份编译共用一个上限，内存紧的设备建议保持推荐值，用单变体编（例如只编 `assembleUniversalDebug`）验证。

如果编译反复在半路消失，先看设备当前可用内存：把它调到可用内存的六成左右再试；实在不够，就关掉后台应用或开系统的内存扩展。

## 环境体检

「设置 → 容器与镜像」下有一块**环境体检**，点「开始体检」会逐项探一遍，把结论直接摆出来：

| 检查项 | 探什么 | 不通会怎样 |
| --- | --- | --- |
| 共享存储访问权限 | 是否已授予「所有文件访问」 | 读不到手机上的文件 |
| 沙箱基础工具 | `sh` / `git` / `curl` / `tar` / `xz` 是否都在 | 对应功能不可用 |
| 容器 DNS 解析 | 能否解析 `github.com` | 容器里下载、克隆全部失败 |
| 容器出网 | 能否访问 `api.github.com`（看 HTTP 状态码） | AI 下载依赖、拉取模型会卡住 |
| 容器残留进程 | 上次运行时遗留的容器进程是否还在跑 | 白白占着内存和 CPU |

状态点四种颜色：**绿**正常、**黄**需要处理、**红**出错、**灰**探测不到（沙箱正忙或没启动）。灰色不是故障——拿不到结果和查出问题是两回事，不会计入待处理项。

每项都会写明**具体原因**，而不是笼统一句「配置有问题」。比如基础工具那项会直接点名：「已就绪 4/5，缺少：xz」。

### 容器残留进程

App 被系统杀掉时，它启动的容器进程有可能变成孤儿继续留在后台。体检会核对每个进程的身份（进程号 + 启动时刻 + 本次开机标识），确认确实是本 App 上次留下来的就**直接结束掉**，并报出处理数量；记录里已经消失、或被系统复用掉的，顺手清理。

### 一键补装缺失的基础工具

基础工具那一项如果缺东西，下方会出现**「安装」**按钮，点一下自动装上，装完自动重新体检。

- **包管理器自动识别**：探测容器里有 `apk` 还是 `apt-get`，不用你告诉它是什么发行版
- **包名自动对应**：Debian / Ubuntu 系把 `xz` 放在 `xz-utils` 包里，会自动换成正确的包名
- **装在容器里，不进镜像**：写进镜像要几分钟重建，为一个 `xz` 不值得。代价是**重建镜像后需重新装一次**，界面上有注明
- **失败会给出原因**：装不上时把命令的末尾输出贴出来（多半是软件源不通或包名不对），不用你去翻日志

> 想要一劳永逸（重建镜像也还在），得在该镜像的构建脚本里把包加进基础依赖列表。环境体检只是把「缺什么、怎么补」讲清楚，不改镜像。

## 统一构建日志

本地容器默认将手机 `/storage/emulated/0/log` 映射为容器内 `/root/log`。需要授予 App 对该共享目录的存储访问权限。目录不可写时会告警并改用 App 私有持久日志目录，不要求 root，也不会阻止容器启动；两处都不可写时不添加默认映射。

此映射只提供统一文件位置，不会改变第三方软件自己的日志设置。使用 `aharou-build` 或「配置 → 工具」中的构建模板，才会自动收集该次编译的标准输出、错误输出和退出码，详见[工具管理](./tools)。Android 应用运行日志仍需通过经授权的宿主通道采集。

已有的容器编辑页「额外挂载」可以覆盖默认映射，例如 `/storage/emulated/0/my-build-logs:/root/log`；对应配置通道字段是 `container.profiles.<id>.extra_bindings`。目标为 `/root/log` 时，不会再创建默认共享目录。环境变量 `AHAROU_LOG_DIR` 可以改写构建日志的容器内根目录；使用既有环境变量入口或容器的 `env` 配置，不需要新增一套工具路径设置。新起的命令或终端会话生效，已运行的进程不受影响。

日志在目录内按容器和工作区分流，原始内容可能含敏感信息，不自动脱敏、不自动删除。共享存储不是私有保险箱；远程 SSH 不映射手机目录，日志只留在远端配置的日志根目录（默认 `$HOME/log`）。

## Void ARM64 开发环境

Void Linux 的 aarch64 glibc 根文件系统已接入镜像同步：在官方索引中只选通用 glibc ROOTFS，排除 musl、ISO 和板卡专用文件；按官方 SHA-256 验证后上传，成功后才发布在线条目。若在线列表尚未出现 Void，可先手动导入，不能把同步接入理解为镜像已发布。

继续使用现有 PRoot 执行后端，不会替换、自动切换或删除已有容器。官方来源：[Void 下载页](https://voidlinux.org/download/)。手动导入时选择完整 aarch64 glibc rootfs tarball；OCI 镜像层不能直接当 rootfs 压缩包导入，需先正确导出文件系统。

环境安装菜单识别 XBPS，保持 Void 原有签名仓库，不写入 Alpine、Arch 等其它发行版的软件源。Android 场景选择仓库实际可用的 JDK 17 或 21，安装 SDK 后替换并执行检查 ARM64 的 aapt2、adb；失败不会显示环境就绪。Python 场景补齐头文件及基础编译工具，Rust 场景安装 rust、cargo 和基础编译工具。

这些是工具安装适配，不代表全部项目都已构建通过。特别是 Android NDK 的宿主编译器、JNI、特定 Gradle 插件等仍须按项目验证；普通 ARM64 Linux 编译器不能代替面向 Android Bionic ABI 的 NDK 编译器。

## 自定义镜像

内置 Ubuntu 可作为默认开发基线，如果你要 Debian，或者想要一个预装特定工具链的环境，可以自己加镜像。两种办法。

### 方式一：内置镜像下载（推荐）

1. 打开「设置 → 容器与镜像」，点右上角的下载图标。
2. 页面会列出当前源下已发布的可下载镜像（Ubuntu、Debian、Arch Linux ARM、Manjaro ARM 等；Void 仅在同步发布成功后出现），点一行看详情并下载。
3. 右上角可以切换下载源，默认是「Aharou 自建源」，另有官方源 / 华为云 / 阿里云 / 腾讯云。国内网络建议用自建源或国内云源——官方源在部分网络下会极慢甚至连不上。Arch 与 Manjaro 的镜像只有自建源提供（官方没有容器用的精简包，App 同步时自动把它精简后再上传）。
4. 下载完成后点「导入」，镜像就加入容器列表了，选中即可使用。

已下载的镜像可以重复导入；左滑可以删除下载好的镜像文件。

- 如果某个已下载的镜像标着**有新版可下载**，说明镜像目录里的版本已经比你下载时新（上游发了新版本或新补丁）。重新下载并导入即可，旧文件可以先左滑删掉释放空间。
- 下载过程会自动校验文件完整性：Ubuntu、同步发布后的 Void 有官方 SHA-256，校验不一致会提示**文件校验失败**并删除半成品，重下即可；Debian 的可变构建链接未固定校验和，不做该校验。切到华为云 / 阿里云 / 腾讯云等第三方镜像源时也不强制校验（这些镜像是否重打包未经实测）。

镜像列表会给每个版本标出支持状态，依据是发行版官方的支持周期：

- **即将停止支持**：常规支持将在 30 天内结束，建议尽快换成更新的版本。
- **仅延伸支持**：常规支持已结束，只剩延伸支持期（Ubuntu 的 ESM、Debian 的 LTS 等）。这类版本一般仍能收到安全更新，但不建议长期使用。
- **已停止支持**：常规支持与延伸支持都已结束，不再有安全更新，不建议再用于新环境。

仍在常规支持期内的版本不显示标签。挑镜像时优先选支持期还长的版本，省得装完没多久又得回来换。

### 方式二：手动导入镜像文件

需要特定版本或特定发行版时，可以自己准备 rootfs 镜像导入。

**镜像要求**：

- 压缩格式：`.tar.gz`、`.tgz`、`.tar.xz`、`.txz`
- 内容必须是完整的 Linux rootfs（文件系统根目录，里面有 `/bin/sh` 或其它 shell）
- 仅接受原生 ARM64（aarch64）镜像；Alpine、x86/AMD64 与 32 位 ARM 即使改名也不受支持

**从哪里拿镜像**：

- Ubuntu：`https://cdimage.ubuntu.com/ubuntu-base/releases/`，选 `ubuntu-base-*-base-arm64.tar.gz`
- Debian：可以从 Docker Hub 的官方镜像（如 `arm64v8/debian`）导出
- Arch Linux（ARM）：`https://mirror.archlinuxarm.org/os/`，选 `ArchLinuxARM-aarch64-latest.tar.gz`。官方包面向 ARM 开发板，包含内核与固件（几百 MB），容器里用不上这些，导入后可在容器里自行精简，或直接用内置下载里的 Arch 精简包
- Manjaro（ARM）：GitHub 上的 manjaro-arm/rootfs 仓库每周发布，`https://github.com/manjaro-arm/rootfs/releases`，选 `Manjaro-ARM-aarch64-latest.tar.gz`
- Fedora：`https://dl.fedoraproject.org/pub/fedora/linux/releases/`，进对应版本的 `Container/$arch/images/` 目录选 `Fedora-Container-Base-*.tar.xz`（官方容器镜像，本身就是精简 rootfs）
- openSUSE：`https://download.opensuse.org/ports/aarch64/distribution/`，进对应版本的 `appliances/` 目录选镜像

**通用方法：从任意 Docker 镜像导出 rootfs**：

```bash
docker pull --platform linux/arm64 debian:bookworm
docker create --platform linux/arm64 --name temp-rootfs debian:bookworm
docker export temp-rootfs | gzip > debian-rootfs.tar.gz
docker rm temp-rootfs
```

有 Docker 的话这是最通用的路子——Docker Hub 上几乎所有发行版都有官方镜像（`arm64v8/ubuntu`、`arm64v8/fedora`、`arm64v8/opensuse` 等），导出即得完整 rootfs。

也可以在已有的 Linux 环境里用 `debootstrap`（Debian / Ubuntu）自己做，Arch 用 `pacstrap`。

**选镜像的三条硬规则**：

1. **架构必须匹配**：本地仅用 aarch64/arm64 镜像，安装和启动会检查实际 shell 的 ELF 架构，不能仅凭文件名判断。
2. **优先容器版而非桌面版**：带桌面环境的镜像（如 Ubuntu 桌面 ISO）体积巨大且无头容器用不上，选 `base`/`minirootfs`/`Container-Base` 这类最小变体。
3. **shell 不能缺**：rootfs 里至少要有 `/bin/sh` 或 `/bin/bash`，否则容器起不来。

**导入后包管理器支持**：App 能自动识别容器里的包管理器并按需补装基础工具，本地支持 apt-get（Debian/Ubuntu）、pacman（Arch/Manjaro）、xbps（Void）、dnf/yum（Fedora/RHEL 系）。其他发行版没识别到包管理器时，自动补装会提示「认不出包管理器」，手动装工具即可。

**导入步骤**：

1. 打开「设置 → 容器与镜像」，点右上角 +，选「本地镜像」。
2. 填配置：
   - **名称**：这个镜像配置的别名。
   - **shell 路径**：容器内的 shell，如 `/bin/sh` 或 `/bin/bash`。
   - **镜像文件**：选择准备好的 rootfs 文件。保存时会复制一份到 App 私有目录，之后重置容器都从这份副本重新解压，不依赖原始文件；删除镜像时副本一并清理。
   - **挂载**（可选）：把手机里的目录挂进容器，详见下面的「把手机目录挂给 AI 用」。
   - **proot 参数**（可选）：逐项添加，原样追加到 PRoot 启动参数。
   - **环境变量**（可选）：注入容器内进程的键值对。
3. 保存后在列表里选中这个配置，就切换成了自定义容器。

首次使用自定义镜像时 App 会解压 rootfs 到私有目录，耗时取决于镜像大小。自定义镜像默认不配国内软件源，首次进终端的初始化菜单里可以换。

### 常见问题排查

**装软件报错**：容器内硬链接不可用导致的。编辑镜像 → proot 参数 → 添加 `--link2symlink` → 保存，重进终端。用内置下载功能导入的镜像已经默认带了这个参数。

**方向键显示成 `^[[A`**：当前 shell 是 `sh`，没有行编辑能力。编辑容器，把 Shell 改成 `/bin/bash`，它自带方向键、历史记录和补全。

## 容器里的内置目录

App 每次启动容器都会自动挂好下面这几条目录，AI 和终端一进去就能用：

| 容器内路径 | 里面是什么 |
| --- | --- |
| `~/workspace` | 当前工作区。切工作区就是换这里的内容 |
| `~/shared` | 跨工作区共享区，所有工作区共用同一份（见下一节） |
| `~/.aharou` | AI 配置目录：`skills/`、`docs/`、`mcp.json` 等 |
| `~/.aharou/memory` | 记忆：SOUL.md、核心档案、日志 |

（`~` 展开后就是 `/root`；`~/.aicode` 是 `~/.aharou` 的旧路径别名，两边内容完全一样，不用管。）

这些目录都存在 App 私有存储里，跟容器镜像分开存：换镜像、重置容器都不会动它们；反之删掉容器也不影响。要在里面放东西，除了在终端里直接操作，也可以让 AI 去做。

## 把手机目录挂给 AI 用

AI 跑在容器里，默认只看得到工作区，看不到手机的公共存储。要让它访问，得把手机上的目录挂进容器：

1. 先确认存储权限已授权。首次使用时会弹权限请求；之前拒给过的话，去系统设置 → 应用 → Aharou → 权限 → 存储 里开启。
2. 打开「设置 → 容器与镜像」，编辑当前正在用的容器。
3. 在「挂载」里加一条：**本地目录**填手机上的路径（例如 `/sdcard/Download`），**容器目录**填容器内路径（例如 `/mnt/Download`）。
4. 保存后重启终端会话，AI 就能通过容器内路径访问了。

::: warning 按需挂载
只挂你需要的子目录，不要图省事直接挂整个 `/sdcard`——那等于把手机里所有文件都暴露给 AI，有隐私泄露风险。
:::

例子：想让 AI 自己看 App 的日志，把本地目录 `/storage/emulated/0/Android/data/com.aharou.agent/` 挂到容器 `/mnt/aharou`，它就能读 `/mnt/aharou/files/logs/` 下的日志。注意 `Android/data/` 下只能访问 Aharou 自己的目录，其他应用的目录受分区存储限制访问不了。

如果只是想处理某一个文件，更简单的办法是把它复制进工作区，AI 默认就能访问。

## 跨工作区共享目录

每个工作区都有自己的目录，切工作区就换了地方。如果你想在所有工作区之间共用同一批文件（常用脚本、素材、模板），把它们放**共享区**里：

- 容器内路径：`~/shared`（也就是 `/root/shared`）
- App 内入口：聊天页顶栏的「打开共享区」按钮，点开就能浏览、传送文件
- 手机上的位置：挂在 App 私有目录里，用系统「文件」管理器挂载 Aharou 后能看到（见〈文件浏览与代码编辑〉）

用法举例：把常用的构建脚本放进共享区，然后对 AI 说“用 `~/shared/build.sh` 编译当前项目”；或者把素材图片丢进去，在任意工作区都能引用。

::: tip 和工作区的区别
`~/workspace` 是**当前工作区**的目录，切工作区就换了；`~/shared` 是所有工作区**共用**的，切了也不变。只属于某个项目的文件仍旧放 `~/workspace`，不要往共享区堆。
:::

::: warning 共享区不在备份里
「备份与恢复」不包含共享区里的文件，重要内容请另外留一份。
:::

### 跨工作区信箱

不同工作区之间是故意隔开的：会话记录、记忆都互相看不见。如果你想让 A 工作区的 AI 给 B 工作区留句话（“TODO.md 第 5 条可以开始做了”“素材放进 `~/shared/drafts` 了”），用它：

- 位置：共享区里的 `~/shared/inbox/`，每个工作区一个文件，文件名形如 `software-1a2b3c4d.md`（目录名 + 一段短哈希）。文件在你第一次真往里写消息时才出现，没用的工作区不会凭空多出空文件。
- 一行一条消息，格式是 `- 2026-10-20 15:40 [软件工作区] TODO.md 更新了，第 5 条可以开始做`，人和 AI 都能直接读写。
- 门牌号：每个工作区自己的地址在它的系统提示里；**全部工作区的地址表**在 `~/shared/inbox/workspaces.md`（工作区通讯录，App 自动维护，随工作区增删自动更新，手改会被覆盖）。给别的工区留话时 AI 查这张表，不用猜文件名。
- 怎么留：直接对 AI 说「给写作工作区留一句：素材放在 ~/shared/drafts 了」，它会自己找对文件写进去。
- 怎么收到：消息写进信箱就会自动送到目标工作区**最近的会话**——它空闲时直接开始一轮来处理，正忙就等这一轮结束再送达，**不用你切过去**；切回去或它自己开始新一轮时也会捞到未读。App 没开着（进程被杀）时不投递，下次打开再送，消息不会丢。同一批消息只提醒一次；它是留言而不是聊天，想立刻让对方干活还是直接在那儿说。
- 信箱里的内容对 AI 只算参考信息，涉及删除、推送这类不可逆操作时它仍会按原规则向你确认。
- 投递回执：消息被取走时 App 会往 `~/shared/inbox/delivered.log` 追一行——时间、目标工作区、投递方式、取走它的会话、消息摘要，一行一条，最多保留最近 500 行。发送方据此能确认「到了没、什么时候被谁取走」；它只记旁证，不影响队列语义。
- 只放跨工作区真正必要的信息（谁改了什么、下一步该做什么），不要把大段对话倒过去。

::: tip 换路径与清空
信箱文件的身份是工作区的完整路径：把目录搬走或改名，就会变成另一个身份、读不到老信箱了（老文件还在 `~/shared/inbox/` 里，没删）。消息投递给收件工作区之后会**自动从文件里删掉**，所以文件里剩下的就是还没送达的那些；想清空直接删文件即可。
:::

::: warning 仅本地工作区
信箱走的是共享区，也就是容器里的 `/root/shared`；远程 SSH 工作区的 `~/shared` 在对端服务器上，跟这个信箱不是同一份，所以远程工作区暂不参与信箱收发。
:::

## 全部删掉会怎样

即使删掉所有容器（包括内置 Ubuntu），App 也不会不可用——AI 执行命令时会回退到内置 Ubuntu 作为默认执行环境。重新打开「容器与镜像」页，在空状态页面可以一键恢复内置 Ubuntu 或添加新镜像。
