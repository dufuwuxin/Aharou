# 记忆库

记忆库只在「配置」页面提供入口，「设置」页面不再重复显示。内置主代理约定、成员约定、模式提示及辅助请求都是这里的原生条目，可以编辑、停用或删除。后台自动整理不会合并或压缩这些指令条目；停用和删除后不会恢复旧提示文件，也不会在下次启动补回。

在配置页打开「记忆库」，直接创建和管理内容。记忆库只在配置页提供入口，不在其他设置分组重复显示。页面提供「内容库」「注入预览」「关系图谱」：分别用于管理条目、检查当前注入结果和查看真实关系。

应用管理的注入文字统一来自这套原生记忆库，包括内置行为约定、模式提醒和成员专属约定。内置内容也作为可见条目管理，可以查看、编辑、停用或删除；不会在下次打开时偷偷恢复已删除的默认内容。修改保存后，下一次相关请求读取当前条目，不需要改旧提示文件。

## 跨模型执行契约与来源

记忆库新增「主代理执行契约」「成员执行契约」和「执行机制来源与适配」。前两条分别进入主代理和成员请求，强调正常授权任务直接推进、按真实工具参数调用、核对结果、失败恢复与准确交付；后者仅检索，记录六个参考仓库的用途、许可、原文指纹、适配点及未导入内容，不把整仓资料放进每次请求。

多步执行使用内置 `task-execution` 技能；专业角色通过成员原生条目的职责与交付判据起作用，不会因为修改旧角色文件就自动注入它的正文。工具目录只负责发现，展开参数和实际执行仍是独立步骤，原有权限设置不变。

旧版本升级只一次性增加上述三个新条目，不刷新已有内置正文。用户对同名条目的修改、停用、改名或删除继续保留；安装记录损坏时保留现有内容并暂停补入。保存和种子回归证明加载机制，不证明所有模型已具备相同能力。

这套契约不依赖某个 GPT 或特定国产模型。模型的实际工具调用、图片、上下文和结构化输出能力仍以服务接口为准；没有对应模型的受控测试时，效果记为未验证，不承诺完美执行或绕过服务限制。完整六来源可在记忆库搜索「执行机制来源与适配」查看。

## 内容类别与文件夹

- **规则类**：必须遵守的行为要求，新建时默认带入正文。文字约定不代替工具授权。
- **临时存放类**：绑定一条明确选择的对话，只在那条对话使用。重新打开同一对话仍可读取，不会带入其他对话，也不会自动删除。
- **长期类**：以后还要使用的资料、事实和经验，新建时默认仅检索。
- **角色注入**：每个角色都会使用的背景、偏好与约定；即使角色未开启普通记忆，也会按使用方式带入。不会进入主代理。
- **主代理注入**：只供主代理使用，不带入角色。旧的「注入类」保守归到这里，不会自动扩散给所有角色。

角色注入与主代理注入各有一个默认文件夹，从对应类别顶层新建时自动带入。两个文件夹仍使用同一记忆库，不生成条目副本；旧的「内置默认」目录会合并到对应的注入目录，已修改的正文、标题、停用状态不变，已删除的内置条目不会补回。

每类都可以创建多层文件夹；页面从当前类别的根目录开始，逐层显示直接子文件夹和当前层条目，不把各层正文混成一个列表。点击文件夹进入下一层，用「返回上一级」返回父文件夹。条目可在编辑器中改名、改分类、文件夹和使用方式。文件夹只组织内容，不改变权限或对话隔离。全局条目可跨项目使用，项目条目只属于当前工作区。

辅助请求统一放在规则类的「辅助请求」目录，不再为每个文件单独建文件夹。旧请求目录下的现存原生条目（包括自定义请求）会自动整理到这里；改名或移动到其他文件夹仍保留请求用途，停用或删除仍立即生效。迁移不会导入旧提示文件，也不会重置默认安装记录。

## 新建、查找与编辑

1. 选择类别与范围，从根目录逐层进入目标文件夹，也可以在当前层新建子文件夹。
2. 点击「新建记忆」，选择使用方式，填写标题、摘要与正文。三项内容始终可编辑；选择「摘要索引」也不会隐藏或清空正文。分类、文件夹与范围集中在可展开的附加设置中。
3. 临时存放类还需选择目标对话；没有可选对话时，先创建一条普通对话。
4. 输入关键词会搜索当前工作区可见的整个记忆库，匹配标题、已有的关键词、摘要与正文，不限当前类别或文件夹。多个词需要全部命中，可以分别命中不同字段。结果按相关性排序：完整标题优先，其次是标题、关键词、摘要与正文；重复堆砌正文不会提高排名。界面还可用来源路径查找，结果显示所属类别、文件夹、来源路径与命中片段；清空搜索后恢复逐层浏览。进入文件夹后仍可按范围、使用方式筛选。管理页面可以查到停用条目，查到不等于恢复注入或授予工具权限。这是本地关键词排序，不是可信度评分、向量检索或知识图谱。
5. 打开已有条目可以修改名称、说明和正文。切换类别后，帮助说明跟随当前类别；保存时保留改过的名称。

编辑器内返回会先退出编辑器，有未保存改动时先提示；文件夹内返回先回父级，不直接跳到配置首页。

保存失败会保留草稿。原内容已变化，或编辑期间切换了工作区时，应重新打开当前条目、核对后再保存，不会静默覆盖另一项目的同名内容。删除条目只针对所选条目。

进入自建文件夹后，可点击「删除文件夹」，在确认框选择「全局」或「项目」范围。删除会清理该范围、当前类别下的文件夹及其所有子文件夹，并把其中的条目全部移到所选文件夹的上一级；正文、标题、停用状态及辅助请求用途不会改变。空文件夹也可删除。其他类别、其他范围及其他工作区不会被处理；若同名目录仍有另一个范围的内容，它会继续显示。角色注入和主代理注入的默认目录不提供删除入口。

确认期间内容、目录或工作区已变化时，操作会失败并保留确认框；取消后重新打开，核对当前状态再试。

## 四种使用方式

| 方式 | 行为 |
| --- | --- |
| 正文常驻 | 尝试每轮带入全文；超过单条或总预算时整条回退摘要，不截成半段 |
| 摘要索引 | 只提供标题和摘要，正文需要时再读取 |
| 仅检索 | 不自动注入，需要时通过搜索或读取取回 |
| 停用 | 暂停自动注入，条目仍可管理和读取 |

类别决定新建默认值，最终以条目显示的使用方式为准。待确认内容不会被当作已确认规则全文带入。角色注入和主代理注入也必须遵守停用、过期、工作区和内容预算；正文超过单条或总预算时仍整条回退摘要，不扩大预算。普通记忆继续服从角色的记忆设置与记忆区块开关；这两个普通记忆开关不代替专属注入条目的「停用」。临时存放类仍只在绑定的会话注入，角色不会因此获得其他会话的临时内容。

## 注入预览

输入准备处理的任务，选择目标对话并生成预览，检查正文、索引与未带入原因。这里展示主代理的规划，不包含角色专属注入；角色注入需在角色实际请求中确认。预览是当前记忆库的规划结果，不是历史请求记录，也不是整份系统提示词的审计记录。

应用内置的注入文字同样通过原生条目使用；停用或删除后保留为空，不回退到旧提示目录或旧角色正文。已有提示文件不会机械导入，也不会因此批量删除用户文件；旧人格页、来源页和提示文件不再是请求的备用文字来源。

技能、团队与工具在需要的条目中只提供标题、摘要及结构化入口，正文按需读取，不把整篇内容常驻塞入请求。默认工具目录分别作为主代理与成员原生条目首次安装，不覆盖用户已有条目；停用、编辑或删除仍以用户选择为准。目录只列本轮允许的工具名称、描述与发现入口，不自动展开全部参数。工具是否注册、参数结构和执行权限仍由工具执行端决定，编辑记忆中的说明不能授予权限或改写真实参数。

保存成功只表示当前条目已写入；实际请求还受受众、工作区、使用方式和预算约束。请分别核实预览与实际使用，不把保存当作已经发送或跨设备同步。

## 团队与成员

主代理只查看团队名称与介绍，再把任务交给团队执行；不直接选择、创建或联系单个成员，团队目录不展开成员名单；同一工作区已保存的主/成员会话过程可通过会话工具互读，运行中的上下文构成仍仅当前会话可查看。成员内部执行链保留，成员专属文字仍按原生条目的受众配置使用，不会把旧角色文件正文直接拼到请求。

## 让助手读写

可以直接让助手搜索、读取或更新记忆。更新前应读取最新正文并使用返回的版本；发生冲突时先核对当前内容，不凭旧摘要覆盖。临时条目由实际调用对话绑定，不替其他对话伪造暂存。

不要把密钥、口令或真实个人信息样本写进记忆。注入时的敏感信息掩码不等于文件加密；保存、预览和实际使用应分别核实。

旧记忆库升级仅一次性添加新的主代理／成员工具目录条目，不修改或恢复旧的用户条目。之后仍可编辑、停用或删除这两个目录条目，重启不会将它们恢复。目录正文受原有预算约束，完整名称与描述通过目录入口分页读取，参数按需展开。

## 世界书规则

世界书不是另一套内容库：激活条件、角色绑定及关系边和正文一起保存在原生记忆文件的 frontmatter 中，不复制角色文件，不补回已删除的条目。没有世界书字段的旧记忆保持原来的加载行为。

编辑条目时使用「编辑世界书规则」表单设置触发词、排除词、优先级及可展开的角色、可信度与重要性；完整规则也可在默认收起的高级 JSON 中查看和修改。新建、普通保存及改名均随此条原生记忆保存。JSON 无效或数值越界时不能保存，草稿保留，原有内容不变。空对象 `{}` 表示不增加激活条件。也可以通过 config 的 `context_library.entries.<条目ID>.worldbook` 字段读取或设置同一份规则 JSON。

```json
{
  "enabled": true,
  "triggers": ["Android", "Kotlin"],
  "excludes": ["忽略背景"],
  "matchAll": false,
  "caseSensitive": false,
  "priority": 10,
  "roles": ["代码审查"],
  "audiences": ["ROLE"],
  "confidence": 0.6,
  "importance": 80,
  "relations": [{"target": "相关记忆名称", "type": "RELATED"}]
}
```

- 关键词来自**本轮用户输入**，不拿历史消息、记忆正文或模型输出凑条件。有关键词或排除词却没有本轮文本时，不猜测激活。`matchAll` 决定全部匹配还是任一匹配；排除词命中优先拒绝，默认不区分大小写。
- `roles` 是精确的角色名称标签，不做模糊匹配；运行上下文没有角色时不会命中。`audiences` 可选主代理 `MAIN` 或角色 `ROLE`。这两项只能收窄原有分类的受众，不能把角色注入变成主代理注入。
- `priority` 越高越先占用原有预算，同优先级保持原顺序。每条全文不超过 900 字符，全文合计 3000 字符、索引合计 6000 字符；超限仍按原规则回退索引或省略，不因关键词命中突破预算。
- 停用、仅检索、临时会话、项目隔离及角色普通记忆开关继续生效。仅检索条目不会因关键词命中而自动插入正文；原有显式检索也不变成世界书自动激活。
- `confidence`（0 到 1）和 `importance`（0 到 100）只是可编辑的用户标注，不代表系统核验结果，也不影响真实性或授权。关系类型支持 `RELATED`、`SUPPORTS`、`CONTRADICTS`、`SUPERSEDES`，用于检索目标名称及预览解释，不自动传播激活，也不裁决冲突；本轮不提供图谱画布。

「注入预览」按输入的本轮用户文本预览主代理视角，与实际请求使用同一个选择器。角色受众的实际效果取决于真正运行的角色名称与记忆开关，主代理预览不会冒充角色请求。只有元数据不合法的条目会被禁用世界书激活，不影响其他记忆。


## 关系图谱

「关系图谱」从当前工作区可见的原生条目生成，每条记忆一个稳定节点。新保存的关系采用作用域与工作区绑定的稳定图谱身份，改名后仍指向原实体；旧条目 ID 和历史标题保留为兼容引用，未保存过的同名歧义不猜测。全局与项目同名不会擅自选一个。同名歧义和不存在的目标标为「未解析」，不会创建外部或演示节点。

画布每页最多 8 个节点，显示本页节点间的连线（最多 24 条）；点击编号节点或下方同名按钮，沿原入口编辑该记忆。节点下方保留全局／项目、类别与来源说明。关系列表明确方向、关联／支持／矛盾／替代类型、原始目标和解析状态，并可打开来源与已解析目标。每个节点页列出该页条目发出的全部关系，关系较多时每 12 条分页；跨页目标仍保留在列表中，不因画布限额丢失关系。

没有关系时显示真实空态，可点击「编辑规则」回到内容库选择条目，再展开高级 JSON 填写关系。图谱仅查看已保存关系，不是隐式激活传播，也不改变项目、会话、角色、使用方式或工具权限。

## 云端记忆查询

云端查询与本地记忆检索、Git 仓库同步是三件独立的事。云端查询默认关闭且地址为空，不内置第三方服务，也不会把本地结果冒充云端结果。

在原「记忆同步」区域的「云端记忆查询」中，填写自己部署或信任的查询接口地址，然后打开「允许显式云端查询」。接口必须使用 HTTPS，地址不能带用户名、密码、查询参数或片段；这里填写的是查询 API，不是 Git 仓库地址。没有默认可用服务器，也不提供认证配置：需要认证的服务暂不支持，不会自动使用模型密钥、Git 凭据或其他令牌。

需要云端资料时，明确让助手使用云端记忆查询，并给出本次关键词与返回条数（默认 5，范围 1–20）。工具按需发现并沿用现有权限审批流程；开启设置或保存地址本身不会发起请求。请求只发送这次提供的关键词与条数，不附带整个记忆库、聊天历史、角色提示、工作区路径或凭据。不要把秘密写进关键词。

所有返回内容都是**未核验参考**，来源名称是外部服务自己的声明，不代表应用验证过的本地路径；服务端给出的置信度也不变成应用可信度。结果不会执行指令、自动保存到记忆库或自动加入后续注入。与其他外部资料一样，使用前需要核查。

关闭开关、未填地址、格式错误、超时、HTTP 错误、跳转、无效返回或超限都会明确报错，不会自动转为本地搜索、打开开关或改地址。遇到跳转应填写最终 HTTPS 接口地址；遇到超限应让服务减少结果条数或正文长度。单次响应最多 1 MiB、20 条，标题最多 1000 字符、正文每条最多 32000 字符、来源最多 2048 字符，全部字段合计最多 100000 字符；取消会中断请求。


### 检索标签与权重

世界书高级规则支持 `tags`、`keywordWeight`、`tagWeight` 和关系的 `weight`。权重范围为 0 到 8，默认 1；权重为 0 时该项不贡献命中。关键词、标签、摘要和正文只计最强匹配，不因重复正文加分；多个查询词仍需全部命中。重要性在已命中条目间做有限加权，不会凭空产生结果；可信度只是用户标注，不参与真实性裁决或工具授权。
