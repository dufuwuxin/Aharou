# 子代理与角色卡

在底栏「配置 → 角色管理」查看、创建、编辑和删除角色卡。团队页点「创建角色卡」会直接打开空白创建表单，保存或取消后回到团队页，不再绕到角色管理列表。角色管理页提供并发上限、成员互通开关和团队入口；互通设置只影响运行中的成员，不会让静态角色卡自动运行。

角色卡保存职责、提示词、工具范围和模型配置；加入团队后，它才是该团队的成员或管理员，实际派发时才产生运行中的子代理。在配置 → 角色管理中点右上角「＋」定义卡片，不会自动把它加入所有团队；团队页的「创建角色卡」与角色管理列表中的「＋」使用同一个创建表单，各自返回原来的页面。在团队详情点管理员或成员名称可查看对应角色卡，返回后回到团队；引用缺失会明确提示，不显示一张虚构卡片。

升级只更新能由历史内容指纹证明未被编辑的内置角色和团队。用户新增或修改的同名文件不覆盖；退役且未修改的内置预设移入配置根的 `builtin-archive/<类别>/<内容指纹>/<原相对路径>`，保留原始字节。需要恢复时先确认没有同名定义，再将存档复制回相应目录；不要覆盖自己后来编辑的文件。未知来源保持原样，禁用设置不重置。

::: tip 版本说明
子代理从 v1.11.0-dev 起提供。
:::

子代理是由主会话派生出的独立工作会话。当你面临耗时较长的调研、多模块并行审查或架构对比等复杂任务时，可以让 AI 派发子代理并行处理，**不阻塞当前主对话**。

子代理拥有自己独立的上下文与工具能力。派发后它会在后台独立工作，你可以留在主会话继续讨论，也能随时点进子会话查看实时进度、补充提问或手动暂停。

子代理分为两种：
- **默认通用子代理**：自动继承父会话的模型配置与全部可用工具；
- **自定义子代理**：支持自由指定模型、工具白名单/黑名单以及专属提示词。

## 怎么用

在主会话中直接向 AI 提出派发需求即可，例如：

- 「派个子代理去审查 `app/build.gradle.kts`，把潜在问题列出来」
- 「同时派两个子代理，一个调研数据库迁移方案，一个调研 UI 组件库选型」
- 「派一个只读调研子代理搞清楚当前的登录与鉴权流程」

AI 派发子代理时，在**非计划模式下会直接启动**，不再逐次弹窗确认（计划模式下仍会先向你确认）。子代理启动后在后台独立工作，主会话随即恢复空闲，可继续接收你的其它指令。

## 侧边栏中的位置与管理

侧边栏会话列表清晰展示了主会话与子代理的父子归属关系：

- **展开与收起**：派生过子代理的会话，行尾会显示子代理数量与展开折叠箭头。点击箭头可展开查看其下属的所有子代理；
- **状态指示**：正在运行中的子代理会显示绿色的运行状态指示灯；
- **独立交互**：点击子代理即可切换进入其会话页，界面与常规会话完全一致，可独立对话、暂停或重新生成；
- **会话操作**：长按子代理项可进行重命名、导出与删除；删除主会话时，其名下的所有子代理会随之一同清理。

## 上下文与信息传递

::: tip 上下文独立与双向同步
子代理与主会话的对话上下文是完全隔离的，它默认不会自动加载主会话的历史漫谈，保证了轻量与专注：

- **任务派发**：AI 在派发子代理时，会自动提炼当前任务的明确目标、关键文件路径、已核实的背景以及约束条件，打包作为初始指令交给子代理。如果你在主会话中手动指示派发，也建议交代清楚关键背景与期望产出；
- **结果汇总**：子代理执行完毕后，主会话会自动收到完成通知，并读取其最终产出为你进行汇总；若主会话当时正在调用其它工具，卡片下方会提示子代理已就绪，并在当前操作后自动跟进处理；
- **全流程追溯**：主会话通常只读取子代理的最终结论，如果你想查看子代理完整的工具调用日志、推导轨迹或中间输出，直接在侧边栏点击进入该子会话即可查看全部详情。
:::

## 与主会话的双向通讯

子代理与主会话之间支持双向异步通讯，互不阻塞：

- **主会话 → 子代理**：主会话可以随时向某个子代理追加消息（补充指令、纠偏，或对已有结果继续追问），**可反复发送**。运行中的子代理会在下一轮操作里收到该消息；已完成或暂停的子代理会被重新唤醒并继续工作；
- **子代理 → 主会话**：子代理在运行中可以主动向主会话汇报关键进展、求助，或提交需要协调、决策的事项。主会话会收到一条系统通知，并可直接回复。

这些消息在界面上以轻量提示条呈现，不占用普通聊天气泡；主会话忙碌时消息会在当前操作结束后自动跟进处理，空闲时则立即触发新一轮。

## 观察成员在做什么（诊断用）

`task(action="read")` 只给直接子代理的**最终**输出，判断不了「它中间哪一步跑偏了」。为此有一个只读的观察通道：

- **向下看**：`observe(direction="down", depth=1)` 看自己派生的下级（`depth=2` 连隔层一起看），默认每个成员给最近 8 条消息；
- **向上看**：`observe(direction="up")` 看自己的上级（父、祖父…），成员据此理解「上游为什么这么派活」；
- **点名看**：`observe(target="代码审查员")`，给标题片段或会话 id，只展开这一个成员；
- **调粒度**：`detail="tools"` 只看工具调用序列（判断是不是在某个工具上反复打转），`detail="text"` 只看对话正文（判断理解有没有偏）；
- **跑偏的三个信号**：同一工具反复拿不到结果、最后一步工具长期没返回（汇报里会标「可能卡在这里」）、正文理解与任务指令不在一个方向上。

边界：只读（不改任何内容、不发消息）、只限同一棵会话树（跨树不可见）、输出是摘要（正文截断、长参数折叠成「N 字」、一次最多展开 8 个成员），不会把某个成员的一大段日志灌进上下文。

## 子代理之间互相对话

普通派发的同批子代理可以互相通气；**团队预设运行还要遵循本次运行的通信策略**：

- 它们能查看同批队友及其状态，但只有同一运行批次、双方都仍在运行的成员可以直发消息。尚未启动的同批任务仍可限额留言，等其正常启动时一次性接收，不由留言触发启动。直发消息只搭在当前轮的后续工具结果里送达，不会唤醒已结束的队友或触发新一轮。
- 每次由父代理启动的成员运行中，总发送最多 **4 条**，给同一个队友最多 **2 条**（双方最多两轮）；单条最多 **300 个 Unicode 码点**。直发与留言共用额度，用逻辑任务身份或会话身份寻址也共用同一队友的额度。重复内容不会再次投递，也不扣额度。重新启动只重置该成员自己的发送额度，查看队友不会重置。
- 通信关闭、不是队友、自发、超长、额度耗尽或任一成员已完成、停止、删除时，都会明确提示原因；无需逐条回执，额度用尽后把其余结论写进最终回答。
- 这些对话只在子代理之间流转，不会污染你的聊天记录；主会话仍可随时用「发消息 / 读结果」跟任一个子代理沟通。

觉得吵或者不想要这种自组织行为，可以关掉：**配置 → 团队 → 允许子代理互相对话**（默认开启）。关闭后子代理只能向主会话汇报，尝试互相通气会直接收到「通信已关闭」的提示；主会话对子代理的发消息、读结果、停止都不受影响。打开总开关也不代表能绕过团队运行的阶段范围、消息额度或重复消息限制。

## 自动派发与手动指定

主会话 AI 的系统提示词里只带一份**部门索引**：每个部门一行，列出部门名、角色数量与几个代表角色（小部门基本全列，大部门只列前几个，例如 `engineering / 10 / AI Engineer、Android Kotlin Engineer、Code Reviewer`），不再把每个角色的用途描述逐条塞进上下文。**AI 默认会自行判断是否拆分并派发子代理，不需要你显式要求**；选角走「部门 + 关键词」路由：

- **自动匹配**：AI 先判断任务属于哪个部门，再给出 2~5 个描述任务功能或领域的关键词，由本地匹配器在该部门内按角色名称与用途描述打分，挑出最对口的角色，关键词**中英文都认**（中文会先按同义词表转成英文再匹配）；关键词一个都没打中时它不会随手拿一个角色凑数，而是拿到可用部门与建议关键词后重新选；
- **查目录再点名**：索引里每个部门只列几个代表角色，所以 AI 不确定有哪些角色名时，会先查一次角色目录（列出该部门/该关键词下的角色名、一句用途与它的工具集，标出「只读」「不能执行命令」这类边界）再点名指定；
- **手动指定**：你也可以在指令里点明部门与关键词（例如「用 engineering 部门、关键词 code review 的子代理看一遍这个改动」，中文关键词同样可以），或直接点名某个角色（例如「使用 Explore 子代理检索一下所有网络请求的入口」）。

## 内置子代理预设

首次启动时，系统会把内置子代理定义释放到全局目录 `~/.aharou/agents/`，开箱即用。**已存在的文件不会被覆盖**，你的个性化修改与删除在 App 升级时都会保留。

内置分三类：

**1. Explore（只读探索）**

只读的代码库探索与逻辑梳理，不做任何改动：

- 仅开放代码与文件检索工具（`readFile`、`list`、`search`、`websearch`、`webfetch`、`loadSkill`），**不含写文件与执行命令的工具**，不触发授权弹窗；
- 模型默认继承当前会话；想换更经济的模型，在 `explore.md` 里填 `provider` 与 `model`。

**2. 研发角色库（16 个）**

角色名与原始提示词来自开源项目 [Agency Agents](https://github.com/msitarzewski/agency-agents)（MIT 许可，完整许可文本随包附于 `assets/licenses/agency-agents-MIT.txt`），只保留与 Android Kotlin、Rust、云端 Python 相关的角色。其中 12 个已改写为面向这三个语言栈的中文短卡，并限定了工具与注入：UI Designer、UX Architect、UI Finish-Gate Reviewer、AI Engineer、Data Engineer、DevOps Automator、Minimal Change Engineer、Mobile Release Engineer、Application Security Engineer、Accessibility Auditor、Performance Benchmarker、Reality Checker。其余 4 个保留英文原文：Code Reviewer、Software Architect、Product Manager、Trend Researcher；其中 Code Reviewer 与 Software Architect 没有写 `tools`，默认开放全部工具（含写文件与执行命令，仍遵守授权弹窗）。

**3. 中文原生角色（7 个）**

- 语言栈工程师：`Android Kotlin Engineer`、`Rust Engineer`、`Python Backend Engineer`，可读写文件，各自只改本侧文件；
- `决策顾问`：在写起来便宜、改起来昂贵的决定点做只读评审，给出支持 / 反对 / 有条件支持；
- 流程角色：`test-writer`（补单测）、`docs-writer`（文档编写与同步）、`migration-checker`（数据库迁移审查）。

**部门分布**（按文件名首段归部门，共 24 个，含 Explore）：

| 部门 | 数量 | 角色 |
| --- | --- | --- |
| engineering | 10 | Android Kotlin Engineer、Rust Engineer、Python Backend Engineer、Software Architect、Code Reviewer、Minimal Change Engineer、Mobile Release Engineer、DevOps Automator、Data Engineer、AI Engineer |
| testing | 4 | Reality Checker、Performance Benchmarker、Accessibility Auditor、Test Writer |
| design | 3 | UI Designer、UX Architect、UI Finish-Gate Reviewer |
| product | 2 | Product Manager、Trend Researcher |
| security | 1 | Application Security Engineer |
| explore | 1 | Explore |
| general（兜底） | 3 | 决策顾问、Docs Writer、Migration Checker |

AI 看到的是按部门汇总的索引，每行只列部门名、角色数与一两个代表角色。你自己添加的角色按文件名首段归部门，`specialized`、`project-management`、`game-development` 等前缀仍可识别。

内置团队预设有「功能交付团队」（架构拆解 → Android Kotlin / Rust / Python 三侧并行实现 → 代码审查 → 集中验证）、「界面交付团队」（视觉与交互设计 → Android 界面实现 → 收尾把关与可及性验收）和「调研评审团队」。

::: tip 建议按需启用
内置角色卡合计 24 个。升级时，内容仍与已知内置版本一致的角色卡和团队会更新；你编辑过或来源不明的文件会保留。已退役且未修改的内置文件会移入归档目录，不直接删除；启用和停用设置保持不变。三个内置团队均提供成员名单和一名管理员，可在团队详情点击名称查看角色卡。主会话 AI 只看到按部门汇总的索引（体量与角色总数无关），但被点名的部门与关键词仍可能命中用不到的角色；用不到的推荐在「配置 → 团队」里禁用（禁用后不再参与选角与匹配，定义文件保留），能让选角更准。
:::

## 自定义子代理

创建自定义子代理有两种方式，效果完全等价（App 内保存后写出的就是同一份 `.md` 文件）：

- **在 App 内新建**（推荐）：「配置 → 团队 → 创建角色卡」，填表单即可，模型可以直接从已配置的供应商里选；
- **手写定义文件**：自己把 Markdown 文件放进对应目录，适合从其它项目拿现成定义或用 git 管理。

两个可选目录：

- **全局配置**：`~/.aharou/agents/<name>.md`，所有项目共享，升级不丢失；
- **项目级配置**：`<项目工作区>/.aharou/agents/<name>.md`，仅对当前工作区生效，可随代码库一同提交到版本控制中。远程模式下这里指的是**服务器上**的工作区，读写经由 SSH 完成。

同名定义时项目级优先。文件由顶部的 YAML 配置（frontmatter）与正文提示词组成：

```markdown
---
name: researcher
description: 只读代码与技术调研：广泛检索代码、查阅网络资料并汇总结论，不修改文件
provider: DeepSeek
model: deepseek-reasoner
reasoningEffort: high
mode: plan
tools: [readFile, list, search, websearch, webfetch]
disallowedTools: [Bash, terminal]
inject: [base, projectRules]
---
你是资深代码调研专家。请先使用 search 定位入口，再用 readFile 深入核实。
输出结论时请务必标注准确的 `文件路径:行号` 引用；未核实推断需如实注明。
```

### 配置项说明

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `name` | 否 | 子代理标识名称，省略时取文件名 |
| `description` | 建议填写 | 简述适用场景与专长，主会话 AI 依据此描述判断何时选用该子代理 |
| `provider` | 否 | AI 供应商名称，省略时继承父会话配置 |
| `model` | 否 | 模型名称，省略时继承父会话配置 |
| `reasoningEffort` | 否 | 思考强度：`none` / `low` / `medium` / `high` / `xhigh` / `max`；整项留空表示不指定（跟随服务商默认） |
| `mode` | 否 | 默认运行模式：`build` / `plan` / `auto`，省略时继承父会话当前模式 |
| `tools` | 否 | 工具白名单。**省略时代表开放全部可用工具** |
| `disallowedTools` | 否 | 工具黑名单，优先级高于白名单，支持 `mcp__*` 前缀通配 |
| `inject` | 否 | 注入的系统规则片段，详见下表 |

### inject 规则片段

| 取值 | 含义 |
| --- | --- |
| `base` | 子代理专用轻量基线：包含工具使用规范与路径约定，轻量且省 token |
| `mainRules` | 完整通用规则：与主会话保持完全一致的行为准则与规则基线 |
| `skills` | 技能支持：注入可用技能清单，允许子代理加载并执行项目技能 |
| `memory` | 记忆支持：注入全局与项目长期记忆摘要，见 [记忆与项目规则](/guide/memory) |
| `projectRules` | 项目规则：注入工作区内的 `AGENTS.md` 或 `CLAUDE.md` 约束，见 [记忆与项目规则](/guide/memory) |

`base` 与 `mainRules` 是同一套规则的简版与完整版，**正常只选一个**。两个同时开不会报错，但会把相互重叠的规则文本注入两遍，白白占用上下文。

若省略 `inject` 字段，默认等同于 `[base, skills, memory, projectRules]`。如果填写 `inject: [none]`，则仅使用你在 Markdown 正文中编写的提示词。

## 团队预设

单个子代理解决的是「一件事交给谁」，团队预设解决的是「一串事按什么顺序交给谁」。它把多个角色按阶段写进一份 Markdown，对话里一条命令就能跑完整个流程：**阶段内并行、阶段间串行**，上游阶段的产出会自动接在每个下游任务的指令前面。可以在设置页用表单建，也可以手写文件（两者产出的 .md 完全一样）。

内置两个示例，首次启动自动释放到 `~/.aharou/teams/`（已存在不覆盖，改动不会被升级拉回）：

- **功能交付团队**：拆解 → 并行实现 → 代码审查 → 集中验证；
- **调研评审团队**：并行调研 → 交叉评审 → 结论汇总。

### 放在哪里

- **全局**：`~/.aharou/teams/<name>.md`，所有项目共享；
- **项目级**：`<项目工作区>/.aharou/teams/<name>.md`，仅当前工作区生效，可随代码库提交。远程模式下同样指服务器上的工作区。

同名时项目级优先，与子代理定义的规则一致。

### 文件格式

```markdown
---
name: 功能交付团队
description: 拆解 → 并行实现 → 审查
stages:
  - title: 需求拆解
    agent: Software Architect
    prompt: 把目标按 Android Kotlin 与 Rust 两侧拆成改动清单，标明文件范围与验收点
  - title: 并行实现
    tasks:
      - agent: Android Kotlin Engineer
        prompt: 实现 Kotlin 侧部分
        writePaths: [app/src/main/java/com/aharou/feature/ui]
      - agent: Rust Engineer
        prompt: 实现 Rust 侧部分
        interfaces:
          - with: Android Kotlin Engineer
            about: JNI 函数签名与错误码
  - title: 代码审查
    agent: Code Reviewer
    prompt: 审查上游改动，按严重度列出问题
---
团队公约：
- 只改任务范围内的文件。
- 不要自己跑全量构建，验证留到最后统一做。
```

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `name` | 否 | 团队名，省略时取文件名 |
| `description` | 建议填写 | 一句话用途，显示在设置页与主会话的团队清单里 |
| `stages` | 是 | 阶段列表，按声明顺序执行 |
| `stages[].title` | 否 | 阶段名，省略时显示「未命名阶段」 |
| `stages[].agent` | 二选一 | 角色名，取自子代理定义（如 `Code Reviewer`） |
| `stages[].department` + `agentQuery` | 二选一 | 不点名时按部门与关键词选角，与手动派子代理的规则一致 |
| `stages[].prompt` | 是 | 该任务要做什么 |
| `stages[].writePaths` | 否 | 允许写入的路径；同一阶段的任务之间不能相交 |
| `stages[].tasks` | 否 | 一个阶段要并行多个任务时，用列表代替阶段上的 `agent` / `prompt` |
| `stages[].tasks[].interfaces` | 否 | 任务要跟谁对齐什么：`with` 写成员名或角色标签，可选 `about` 写对齐内容。展开时会注进双方成员的 prompt（你声明的边 + 指向你的边），解析不到的目标原样标注未解析。编辑页里对应每阶段的「协作对齐」，用勾选成员的方式可视化声明，保存后等价写进文件 |
| `stages[].review` | 否 | 阶段类型：`false` 为执行，`true` 为审核；编辑器直接选择「执行 / 审核」 |
| `stages[].rejectTo` | 否 | 审核驳回时回退的早先阶段标题，必须唯一；不填写则驳回后停止 |

正文是**团队公约**，会拼在每个任务的指令前面。全队共用的约束（改动范围、构建策略、提问方式）写在这里，不必在十几条任务里重复。

### 通信策略与消息额度

团队编辑器可以选择通信范围：

| 策略 | 可以怎样协作 |
| --- | --- |
| 同阶段（`same_stage`） | 只向本次运行同一阶段的队友直接发消息；需要跨阶段协调时向主会话汇报 |
| 主会话转达（`parent_only`） | 不直接联系队友，由主会话负责转达与协调 |
| 本次运行（`run`） | 可向本次运行的其他任务定向留言，包括尚未启动的阶段；仍不能联系历史运行 |

**新建团队默认同阶段**。已有团队文件没有配置通信策略时，保留原有「本次运行」行为，不会因为升级悄悄改变协作范围。

每位成员每次团队运行的消息额度默认 **8 条**，可设为 **1~100 条**。发送前先合并问题、证据和需要对方确认的事项，避免逐条回执；重复消息会被拒绝。通信范围、额度和重复限制由执行层检查，不是只在提示词里提醒；同一目标的相同正文会被拒收，不会因为使用会话编号代替任务编号而绕过。沟通内容是否必要仍需遵循阶段指引，系统不会判断改写后的两条消息是否语义重复。主会话仍负责整体通信与协调。

阶段指引单独作为该阶段的任务指令注入，不与上一阶段产出混成同一种信息；上游交付是证据材料，不会自动扩展接收者的写入范围或任务授权。收到队友消息也不能把原任务边界改掉，范围变更应由主会话明确协调。

### 怎么触发

在对话里说「用功能交付团队做 …」即可，AI 会先列团队再执行；也可以直接指定团队名与本次目标。开工时，每位成员都会收到完整阶段、成员、职责、交接关系和任务编号，尚未启动的阶段也有编号。

执行阶段交付产出、约束、验证、未解决问题和下游事项，并保留原始证据。下一阶段接收上一阶段全部批次的交付原文，不只接收最后一批。失败、等待超时或未被接受的任务不会启动依赖它的下游；团队会明确显示受阻，而不是假报完成。

审核阶段的每位必需成员都要给出一条明确的通过或驳回结论，并附证据与具体修改理由；结论缺失、格式错误不会算通过。驳回会按预设退回指定的早先阶段，把审核原文交给原职责成员，只重跑受影响阶段及其后续，最多两轮。未配置回退目标或达到上限时，主代理收到受阻原因与全部已取得的结果，不额外派协调代理。

队友名单和定向消息只属于本次运行批次，不会混入同一主会话的历史团队。能联系哪些任务取决于通信策略；选择「本次运行」时，可按任务编号给尚未启动的成员留言，启动时随任务交付；团队队友消息只在任务运行中搭车消费，不会单独开启新一轮；已完成成员不会被队友消息唤醒。需要继续答疑时，由主会话明确追加任务；普通单独派发与主会话主动发消息不受这一团队限制。被用户停止的任务不会因普通消息重新启动。应用重启后不会恢复进程内运行批次和待投留言。

### 限制

- 团队不会突破子代理的嵌套上限（主代理 → 子代理 → 孙代理），阶段再深也是在这些层级里编排；
- 同一阶段的任务是并行执行的；数量超过「并发上限」（设置页「子代理」页顶部可调，默认 5、最高 15）时自动分批排队，后一批等前一批完成，不必手动拆阶段；
- 团队会连派多个子代理，token 消耗明显高于单线程，琐碎任务不要用；
- 编译、单测这类全局串行的工作建议放最后一个阶段统一跑一次，别让每个成员各跑一遍——同一个工程并发编译只会互相排队。

## 在设置中管理

成员编辑页的「绑定技能」仅展示当前绑定的技能名称。要添加或移除绑定，请进入「技能」列表，打开对应技能详情，再切换成员右侧的开关；一个技能可以同时绑定多个成员。关键词注入仍在成员编辑页配置，不随技能绑定自动改变。

进入「配置 → 团队」，可以按「当前项目 / 全局」分组浏览所有已识别的子代理。页面顶部的「团队预设」进入团队列表：顶部「新建团队预设」用表单建一份（名称、作用域、阶段与任务都可增删，还有团队公约、通信策略与成员消息额度），点条目可看阶段与成员、编辑、左滑删除。在编辑页展开某个阶段，「协作对齐」区以「A → B：内容」的形式列出本阶段已声明的接口边，点「添加对齐」从成员里勾选来源与目标、填对齐内容即可，至少选两名成员才能建立；删成员时以他为来源的边一并清除。详情弹窗的「协作拓扑」区把全团队的边按阶段列出，一眼看出谁和谁对接。表单保存后写出的就是 teams 目录下的 `.md`，与手写完全等价，想批量改也可以直接用文本编辑器改文件。

- **新建**：点右上角的「＋」。表单里可以填名称与用途描述、选作用域（当前项目 / 全局）、从已配置的供应商中**选定模型与思考强度**、勾选工具白名单与黑名单、开关要注入的提示词片段，最后写 agent 提示词正文；
- **编辑**：点进某个子代理的详情页，点右上角的铅笔图标。改名字会连带重命名它的定义文件；
- **启用 / 禁用**：详情页顶部的开关。禁用后它不再出现在主会话 AI 的可派发清单里，AI 也无法再指名派发它，但定义文件保留，已在运行的子会话也不受影响；
- **删除**：列表里左滑条目，会删掉对应的 `.md` 定义文件，不可恢复。

启停状态存在 `agents.json`，与技能的停用名单同一套约定：全局名单位于当前执行环境的 `~/.aharou/agents.json`，本地模式保存在手机 App 私有目录，远程模式保存在服务器上；两者独立，不会自动迁移或同步。项目级名单在本地模式位于 `<工作区>/.aharou/agents.json`，远程模式仍保存在手机 App 私有目录，按服务器和工作区隔离。两级取并集，任一作用域禁用即生效。
在 App 中切换启停状态后列表会刷新。本地模式下手工修改定义或名单，列表几秒内自动刷新；远程模式下不会监听服务器上的文件变化，手工修改后需退出并重新进入设置页刷新列表。

## 运行机制与限制

- **并发上限**：默认最多 **5 个子代理同时运行**，超出时需等待已有任务完成或手动暂停。这个名额是**整个应用共享**的（不按会话分组，子代理再派出的孙代理也计入），可在「配置 → 团队」页顶部的「并发上限」里调整，范围 1~10；
- **嵌套上限**：子代理还能再派生一级（主代理 → 子代理 → 孙代理），最多 2 层，再深会被拒绝；
- **双向通讯**：主会话可随时向运行中或已完成的子代理追加消息（可重复发送），子代理运行中也能主动向主会话汇报或求助；消息异步送达、互不阻塞。
- **默认模式**：子代理默认继承派发它时主会话的模式。在计划（PLAN）模式下派出的子代理同样只能只读探索，在自动（AUTO）模式下也和主会话一样不再逐次弹窗。自定义子代理可用 `mode` 字段覆盖这一默认值，例如给只读子代理固定 `mode: plan`，让它无论何时被派发都保持只读；
- **授权管控**：派发子代理在非计划模式下不弹窗（计划模式除外）；子代理内部与主会话遵循相同的工具授权安全机制，它尝试写文件或执行命令时同样会触发授权确认弹窗（弹窗会清晰标明来源于哪个子代理）；
- **写路径租约（并行写隔离）**：派发时可以声明该子代理允许写的路径——纯调研传空（只读，写文件类工具会被直接拒绝）、需要落盘传精确文件或目录、确需独占整个工作区才传 `*`。若两个正在运行的子代理可写范围重叠，后派发的会被直接拒绝，需要等前一个结束或改成只读再并行，避免并行写入互相覆盖；
- **完成与否按证据判定**：主会话读取子代理结果时，会基于「是否产出了结论、声称的写入是否真的落盘、是否自述未完成」给出终态。空收场、自述未完成、写入被拦或最终失败都不会被当作完成，主会话会据此补派或自己接手，而不是被一句「已完成」糊弄过去；
- **你手动停止也会告知主会话**：在子会话里点停止、或直接删掉一个正在跑的子代理时，主会话会收到一条「已被手动终止」的通知（而不是执行失败），AI 不会自己重新派一个；并发名额也会立即释放；
- **生命周期**：删除父会话时，其包含的所有子代理会话将一并级联清理；
- **定义改动的生效时机**：新增、改名或修改子代理定义后，已打开的会话仍沿用开场时的清单，**新开一个会话**才能让 AI 看到改动。

## 条件团队工作流

每个团队必须从现有成员名单中选择且仅选择一名管理员。旧文件如果没有管理员或配置了多位管理员，原文件仍然保留，界面提示修正，修正前不能保存或运行。图顶的管理员是组织锚点，不是权限继承父节点，也不会增加递归子代理层级。

在团队编辑器中选择具体的源阶段成员、目标阶段成员，再分别添加执行（EXECUTE）、送审（REVIEW）或驳回（REJECT）连线。可添加多条边实现一对多、多人汇合；多个必需前驱必须全部满足后目标才启动。执行和送审边不能成环；驳回是独立反向边，必须从审核者指向真实上游祖先。同一成员在不同阶段按独立端点定位，阶段改名不改变已保存端点，删除端点后不会悄悄换人。

配置了条件连线后，它们会真正驱动调度：只有参与工作流且前驱满足的成员启动，未连接成员不会被隐式全部唤醒。每个目标只接收自己的必要前驱原文与证据，不广播所有历史产出。审核者必须输出一条明确有效的通过或驳回判定，驳回必须有原因。没有有效判定、执行失败、没有明确回退路线或达到两轮返工上限时，下游不会启动。返工只失效受影响的下游交付，独立分支保留。

图上的箭头不授予写权限、消息权限或新的成员身份，仍使用既有写入租约。没有条件连线的旧团队继续串行执行阶段，并明确标注为旧串行流程；原有“接口协作”边仍只是提示词约定，不是调度连线。团队连线可以通过团队配置通道保存和读取，配置修改只影响下一次运行。

### 分析后的定向交接

成员先分析，再决定是否启动后续。没有结构化选择时，兼容旧行为：当前节点交付后，启用全部既有前向出边；自然语言不会被猜成路由指令。成员也可给出结构化交接，只选既有出边中的具体阶段成员，或明确暂停并填写原因。空选择表示不启动后续，并不代表未选中的审核已经通过。即使某个前驱选中了汇合节点，也要所有必需前驱都完成且明确启用该连线，汇合才启动。审核仍独立要求有效通过/驳回判定，选择交接不能绕过审核判定。非法端点、畸形选择和无理由暂停都会阻断调度。

所有已配置审核节点默认是必需门禁，没有执行成员自行豁免规则。即使显式选择空后继，尚未通过的审核仍使团队结果保持未完成，而不是成功；运行结果列出未选节点与审核门禁状态。汇合仍是AND：所有配置前驱都需要完成并选择该目标，不能把条件分支自动猜成OR。多名审核者同批驳回一个目标时，该目标返工同时收到各审核者身份、原文理由与证据，不会只留下最后一份。

管理员显示在图顶部，成员按阶段分层且同阶段横向排列；灰色虚线只是组织关系，不触发调度。有色有向边才是保存并实际执行的工作流，反向虚线是独立驳回。编辑阶段标题、通信额度或点名成员时，按部门/关键词选角的任务会保留完整字段、端点标识及权限声明，不会被点名表单清空。
