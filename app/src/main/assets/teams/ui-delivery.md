---
name: 界面交付团队
description: 视觉与交互设计 → Android 界面实现 → 收尾把关与可及性验收，适合新页面或界面改版
stages:
  - title: 设计
    tasks:
      - agent: UI Designer
        prompt: 为本次目标出视觉规格：元素清单、颜色与字体角色、各状态外观，沿用工程现有主题。只出规格，不写代码。
      - agent: UX Architect
        prompt: 为本次目标出交互规格：页面与跳转（含返回行为）、每个页面的状态表与状态归属、重建与进程回收等边界场景。只出规格，不写代码。
  - title: 实现
    agent: Android Kotlin Engineer
    prompt: 按上游的视觉与交互规格实现界面，只改本次目标涉及的文件，不扩大范围；规格之间有冲突或缺项时先回报，不自行决定。
  - title: 验收
    tasks:
      - agent: UI Finish-Gate Reviewer
        prompt: 对照上游规格审查实现的界面，给出通过或需返工的判定与问题清单。只评审，不改代码。
      - agent: Accessibility Auditor
        prompt: 审计实现的界面的可及性（读屏、触控区域、字体放大、对比度、焦点顺序），按严重度列出问题与修法。只审计，不改代码。
---
团队公约：
- 只改任务范围内的文件；确实需要动范围外的文件，先用 messageParent 说明原因，等上一层放行，不要擅自扩大范围。
- 设计阶段只产出规格，实现阶段以规格为准；规格没写到的地方沿用工程里已有界面的做法。
- 不要自己运行全量构建或单测，统一由主对话发起并先征得用户同意。
- 交接标明工作树/版本、规格和实现位置、未决项；规格冲突或输入变化时先核对，不复用不匹配的旧验收。
- 视觉判断需对应截图与状态，交互判断需实际操作记录；仅阅读代码的结论标为静态推断。没有截图或设备证据就报告未验证，不冒充完成视觉/可及性验收。
- 仅在要求文件时使用本次运行隔离的产物路径；输入或实现版本变化后重新核对截图与交互证据，不把旧报告当本次验收。仅回复不强制落盘。
- 缺信息先问，不猜；改完不自行提交 git。
