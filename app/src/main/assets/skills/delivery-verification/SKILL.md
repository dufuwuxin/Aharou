# 交付核验

## 目标与边界

证明这次交付满足原验收点，而不是证明工具曾经跑过。
不新增功能、不代替根因调查，不为了转绿降低标准，也不把核验变成执行或发布授权。
本流程自包含，默认使用项目已有检查，不要求安装附加工具或先写测试。

## 执行契约

- 从任务原文列出验收点、不可改变项和授权文件，将每条声明对应到实际差异及需要的证据。
- 先确认交付基线：版本、未提交差异、配置、输入、环境；记录必要的文件哈希，不能只看提交编号。
- 不覆盖既有修改；先识别原有失败，再报告本次引入的失败，无法区分时写明不确定性。
- 写入、构建、联网、安装、发布及破坏性操作遵守现有权限；完整授权足够时不重复索取确认，权限不足不绕过。

## 证据等级与适用范围

| 证据 | 能支持 | 不能推出 |
| --- | --- | --- |
| 文件差异、清单、静态解析 | 资产存在、语法或可检查的结构契约 | 已执行、模型会触发、功能有效 |
| 定向单测与隔离运行输出 | 指定输入下的行为与断言 | 真实入口、外部服务或整机链路通过 |
| 当前版本的集成运行或构建产物 | 被覆盖的链路、类型兼容或产物身份 | 未运行路径、真实设备效果或性能改善 |
| 对应环境的端到端实测、受控对照 | 该入口与条件下的实际效果 | 全场景有效、所有模型等效 |

证据是不同维度，不是较高一行自动覆盖前面所有义务；必须匹配声明与验收条件。
引用他人输出标明来源，未经复核不写成自己实测；文件哈希相同也不能证明历史运行使用了它。

## 按变化选择最小充分检查

| 变化 | 默认检查与升级条件 |
| --- | --- |
| 文案、提示词或资源 | 元数据、路径引用、正文边界、加载契约；声称触发率或效果时另做受控样本评测 |
| 单函数逻辑 | 语法与定向行为用例；涉及边界时加异常、空值、重复执行或权限反例 |
| 跨文件签名、依赖、构建配置 | 调用者与锁定信息核对、最小编译或冒烟；按项目要求再做集成验证 |
| 数据格式、存储或接口契约 | 同时核对生产者与消费者、缺字段和版本边界；迁移与回滚按实际变更验证 |
| 性能相关声明 | 同版本基线、相同输入与环境的前后测量，报告样本量、波动、耗时或内存口径 |
| 用户入口、跨进程或外部服务 | 验证真实入口、分支条件与失败恢复；直接调用内部方法不冒充端到端 |

只选择与改动相关的项目，不默认全量构建、全量测试或对所有任务执行测试先行。
项目明确规定的强制闸门仍须执行；不能因最小化检查而省掉它们。
依赖变更不能仅以安装成功验收，还要核对来源、版本、兼容性及受影响运行路径。

## 工具选择、失败与证据缺口

1. 先用项目已有检查，记录实际命令、工作目录、版本、关键输出、退出码及断言覆盖范围。
2. 看测试数量和断言内容；零用例、任务被跳过或只有成功退出码，不足以证明预期行为。
3. 缺工具或环境就列出缺口，能做静态检查时照做，但不改名冒充编译、集成或性能实测。
4. 命令失败保留脱敏错误，区分原有失败、新回归与环境受阻；不删测试、改阈值或反复重跑掩盖失败。
5. 输出冲突先核对版本、输入、缓存及统计口径；上下文缺失就保留未验证，不选好看的结果。
6. CI 必须对应实际提交与工作流运行，核对状态和具体步骤；仅提交任务或看到旧成功记录不算通过。
7. 本地成功与 CI 成功分开报告；无远端证据则写 CI 未验证，不把计划运行写成已运行。
8. 跨模型效果使用固定正常任务集、同一工具与输入版本做对照，逐模型记录完成、误拒绝、失败、越权与成本。未调用的模型写未验证；不以身份口吻或提示词更强硬推断能力提高。
9. 吸收外部技能时预留独立验收样本，避免用提炼时见过的案例自证；来源、许可、内容指纹、适配落点与未导入项均可回查。

## 自检与中断恢复

- 每项状态收敛为「已证实」「证据证明不适用」或「未验证」，不遗留未说明的待办。
- 再看差异是否越界、证据是否仍匹配当前文件、结论是否超过检查能力；复用有效证据，不机械重跑。
- 中断时保留版本与输入、已有输出、仍在执行的任务和副作用状态；恢复时先确认任务是否已结束。
- 代码、配置或输入变化会使相关旧证据失效；不能拼接不同基线的成功片段冒充一次完整验证。

## 真实输出契约

按验收点给出：结论、改动路径、证据定位、实际检查及关键输出、检查数量、原有失败、未验证项与风险。
只有证据覆盖原判据时才声明相应范围完成；其余写清已实现、仅静态通过、运行受阻或需人工核验。
不以「文件已写」「命令已启动」「CI 已排队」替代完成；不编造输出、链接、性能数字或模型效果。
日志与证据先脱敏，不包含凭据。构建、运行、发布分别表述，未执行的环节明确标注。
