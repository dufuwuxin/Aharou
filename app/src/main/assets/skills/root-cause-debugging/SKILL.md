# 根因排错

## 目标与边界

找出输入到错误输出之间的首个失真点，以最小改动修复，保留原有成功路径。
本技能只给排错流程，不授予执行权限，不替代项目规则，不要求所有任务先写测试。
没有复现证据时可以给调查方向，但不得把猜测写成已定位的根因。

## 执行契约

- 开始时固定：预期与实际、受影响版本、允许改动的文件、不可改变项、可观察验收点。
- 先记录已有未提交改动和原有失败；只动授权文件，不覆盖他人修改，不把无关失败计入本次修复。
- 读文件与现有测试确认当前行为后再修改；不顺手重构、升级依赖或改变验收标准。
- 写入、联网、安装、破坏性操作及外部副作用遵守现有权限；授权不足时报告边界，不绕过审批或安全检查。

## 工具选择与失败路径

默认使用当前项目已有的只读检索、日志和最小定向运行能力，不假定宿主附加工具。
缺工具、运行环境或必要输入时，列出具体缺口；用静态调用链缩小范围，并把运行结论标成未验证。
命令失败保留脱敏后的原始错误和退出码；先判断产品缺陷、原有失败、环境失败，不能以重跑转绿代替根因。
模型没有行动时，再区分工具未发现、参数不合法、执行权限不足、上下文遗漏、任务粒度不合适和服务方拒绝；先核实际调用与返回，不把每种失败都归因于模型保守。针对正常任务修工具接线和输入契约，不用改写身份或隐藏意图绕过限制。
证据冲突时保留各自的版本、输入与时间，找出口径差异；上下文不足时请求最小必要信息，不编造补齐。

## 阶段一：复现

1. 固定最小输入、入口、配置、版本和运行条件，写清预期输出与实际输出。
2. 首选最小范围的现有失败用例或用户复现路径；排除真实数据写入和外部副作用，必要时隔离夹具。
3. 偶发问题记录触发次数和失败次数，保留时间与并发条件；不能稳定复现就明确写出限制。
4. 尚未确认的问题不靠大批日志或多次试改碰运气；先选择能区分原因的一次观察。

## 阶段二：证据与边界

1. 沿输入 → 解析 → 状态 → 副作用 → 输出追踪，标出最后正确点和最先错误点。
2. 核查同根因的邻近消费者：默认值、缓存、异步回写、权限及跨层字段；不因此扩展写入范围。
3. 每项结论区分已观察事实、推断和待验证项，挂到文件行号、脱敏日志或实际命令输出。
4. 对比正常与失败样本时保持版本、输入及口径一致；不同来源的相似文字不等于同一个事件。

## 阶段三：可证伪假设

1. 一次选择一个具体假设，写出若为真应看到什么、若为假应看到什么。
2. 用最小只读观察或隔离实验区分假设，记录实际结果；不一次改多个变量。
3. 结果推翻假设就撤销该解释，不通过加等待、重试、放宽断言或吞异常维持它。
4. 两次观察都没有新增信息时停止试探，报告缺少的证据与下一项最有区分力的检查。

## 阶段四：最小修复与回归

1. 只修已证实的断点；保留公开契约、数据含义、用户覆盖与权限边界。
2. 按风险选择复现回归与受影响正常路径；重复执行、空输入、异常和并发仅在相关时覆盖。
3. 适合自动化的缺陷补定向回归用例；测试顺序服从项目约定，不把测试先行当通用前提。
4. 比较修复前后的同一输入和环境，确认原故障消失且成功路径未退化；静态检查不能替代运行证据。

## 自检与中断恢复

- 核对改动是否解释复现、证据是否支持根因、是否误改无关文件，复用仍有效的成功验证，不重复跑全量。
- 中断时留下当前版本、改动范围、已验证输出、未证实假设及副作用状态。
- 续作先确认这些输入未变；代码或条件变化后，旧运行结果不得用作新版本已修好的证明。

## 真实输出契约

交付包含：故障与根因、证据定位、实际修改路径、验证命令与关键输出及退出码、原有失败、未验证项和残余风险。
明确分开「已修并验证」「已改但未实跑」「仅有假设」「受阻」；无实际运行就不声称回归通过。
所有日志先脱敏；不回显凭据，不把读取成功、命令提交成功或进程退出当成功能正确。
