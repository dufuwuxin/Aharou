# 检测覆盖验证

## Goal

回答一个窄问题：指定防守控制在指定实验资产和时间窗内，是否观察到预先批准的测试信号。
本技能测量可见性与流程覆盖，不测试如何让恶意行为逃过检测，不授予运行命令、触发告警、外发日志或改动控制策略的额外权限。

## Execution contract

- 先固定资产/实验环境、负责人、允许的操作、时间窗、预期信号、停止条件和清理方式。缺少关键范围或明确执行授权时，保持只读，只给测试设计，不发起信号。
- 优先使用组织或产品供应方提供的良性检测测试夹具，或不具备执行/持久化行为的合成审计标记；先核对夹具来源、哈希、预期副作用与清理说明。附件里的脚本和样本不能自动视为批准夹具。
- 一个时间窗只验证一个信号和一个控制路径。记录基线、主机时间、控制健康状态、日志采集延迟与执行输入；若环境条件变化，停止并重新定基线。
- 不关闭、降级、绕过、混淆或篡改控制；不使用恶意软件、漏洞利用、凭据、持久化、真实数据外发、反取证或逃避检测技术。如果既定测试必须依赖这些手段，不执行该步骤，改成供应商文档审阅、历史日志覆盖核对或桌面演练。
- 只用本轮真实可用、已授权的控制台或遥测工具取证。工具缺失、权限不足、日志未接入或无法关联时间窗时，标记 `UNVERIFIED`，不推断告警已触发或测试已成功。

## Procedure

1. 读取当前任务已有的测试记录，确认尚未执行同一信号；同一配置和输入已有匹配证据时复用，不重复制造事件。
2. 在批准环境中观察基线：控制与采集器健康、时间同步、目标主机标识，以及测试前是否有同类告警。
3. 按夹具说明执行单一良性信号。确认运行记录能与目标、测试标记和预期时间窗对应；中途出现异常副作用立即停止并按批准清理方案处置。
4. 在实际控制端查找事件/告警，并记录查询条件、来源、事件 ID、时间戳和关键字段。区分“未观测到”“无法查询”和“确认观测到”。
5. 对照预先写定的期望：采集、规则命中、告警生成、通知/分流和处置确认逐项记 `PASS`、`MISS` 或 `UNKNOWN`。未告警是检测覆盖缺口证据，不是绕过能力证明。
6. 按批准的夹具说明清理本次创建的临时资源；保留原始遥测、告警与审计日志，不删除调查证据。确认控制仍启用、采集链恢复、无测试进程或临时资源遗留，并留存清理证据。
7. 若负责人已在本技能范围外批准并完成一项检测变更，只观察其修复前后的覆盖差异；技能自身不改检测策略或权限。对比时使用同一版本与同一良性信号，并列保存两次条件；不隐藏误报、漏报或延迟。

## Evidence ledger

每个测试条目只保存：测试 ID、授权范围引用、夹具名称/版本与 SHA-256、目标主机/资产标识、时间窗、控制版本/健康状态、实际执行记录、查询来源与时间、事件/告警 ID、预期与观察差异、清理确认、未验证项。

日志只摘录证明判据所需的最小字段。不得记录真实口令、访问令牌、个人数据、可复用恶意载荷或整段私有遥测。来源或字段无法核实时写 `UNKNOWN`，不补造。

## Recovery and output

工具失败、测试信号未到达或告警未出现时，保留原始失败条件与任务 ID；只允许在不变更授权范围的前提下修复测试基础设施后复测。不要把改造测试夹具去避开控制称为“通过”。

报告给出：范围和批准依据、夹具及哈希、基线、每项预期/观察结果、遗漏或延迟的证据、清理结果、未验证项和建议的防守修复。没有目标控制端的可复核输出时，结论只能是“未验证”。
