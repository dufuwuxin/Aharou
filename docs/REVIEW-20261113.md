# Native-memory release review

## Scope and limits

This review covers the native-memory-only prompt changes, the settings/configuration consumers, and selected architecture, privacy and performance paths. It is not a proof that the whole application has no bugs, a full Operit2 parity claim, or a device inference/visual benchmark. No device installation or shadow-screen interaction was performed. The older Operit2 acceptance backlog remains documented in `OPERIT2_UPGRADE.md` and is not silently marked complete by this patch release.

## Request construction

- Main/member system prompts are rendered from editable native memory entries. Legacy prompt files, role bodies and project-chat UI suffixes are not fallback prompt sources.
- Mobile operation, cross-check and supervisor requests read named native-memory entries. Missing/OFF entries do not recover hidden Kotlin prompt bodies.
- Resource files, skills, project rules and tool discovery remain readable on demand. Protocol tool schemas and explicit task inputs are not unsolicited default system instructions.
- Stable entries precede dynamic entries; priorities apply within each group. Dynamic data only enters through enabled memory templates and remains subject to the existing per-entry and total budgets.
- The original 35 default entries remain unchanged; nine new IDs are appended. Durable receipts preserve native edits, OFF state, rename and deletion.
- Legacy personality and CORE compatibility settings edit native memory rather than add another injection channel. The one-time profile receipt prevents deleted entries from being restored from the old SOUL file. CORE remains ordinary memory and follows its switch. Migration failure leaves the application usable and does not record success.

## Settings audit and fixes

The settings route dispatcher was inspected together with provider/configuration storage, memory, skills, members/teams, local-model catalog and container/permission sections. Runtime regression coverage is provided by the project tests and CI, not by the presence of a setting alone.

| Finding | Resolution |
| --- | --- |
| Persona/core settings stored values outside the active prompt path | Native-memory compatibility editor and one-time migration; display name/avatar remain appearance settings |
| Ordinary-memory switch had no active injection consumer | Connected it to native-memory planning; native main/member entries retain their independent OFF controls |
| Skill config read effective union but wrote only global scope | Config field now reads/writes the same global scope; UI effective enabling removes both contributing records |
| Mixed-case disabled names could not be enabled reliably | Normalize on scoped reads and writes |
| Second scope write could silently fail | Check the persisted project file; report failure and restore the first scope |
| Auxiliary session lookup errors became main-agent requests | Missing/unavailable sessions stop the auxiliary request; cancellation propagates |
| Editable auxiliary system prompts bypassed privacy masking | Mask system and message text before provider calls, restore returned text/tool arguments |
| Task-store failure could break ordinary prompt construction | Return an explicit unavailable data state, without injecting code-owned behavior instructions |
| Default seed JSON reparsed for every lookup | Cache immutable parsed seed data; keep runtime memory reads fresh |

The mobile-action approval policy was not tightened as a side effect of this review. Screenshots are not text-redacted by the text privacy masker. Large skill-market archives and repeated settings refresh scans were identified as further performance investigation candidates; there are no device measurements establishing their current latency or memory impact.

## Verification

Local targeted tests, the complete remote app/core-agent suites, and the release build are reported separately in the delivery message with their exact SHA/run and artifact identities. A previous build or XML set is not reused to certify a later source change. Static checks and CI do not replace device interaction or inference acceptance.
