# Aharou 2.56：oh-my-pi 借鉴与两轮交付计划

## 目标与边界

以 `v2.55.0-fork.44` / `2e15f99f84549c89ab3af49b1d8beb0f6f1dd19e` 为候选发布基线，借鉴 `can1357/oh-my-pi` 的真实可复用设计，完成两轮实现、独立代码与缺陷审查、CI 验收及 2.56 正式 Release。

不整仓复制上游、不把 Bun/Node/TUI 专属代码移入 Android/Kotlin、不改变模型供应商契约、不降低既有工具/容器能力、不覆盖用户当前工作树的未提交修改。`/root/shared/aharou-current`（`feat/next-model-routing-20261119`）目前比 fork44 少 73 个提交且有大量未提交改动；只读对照，绝不切分支、清理或合并整棵工作树。

## 上游证据和设计假设

- 上游仓库当前公开许可证为 MIT；第三方 vendored 组件仍分别受自身许可证约束。吸收前继续核对具体资产许可证与 NOTICE，不整段复制大型提示词或代码。
- 实际源码/文档已确认：`packages/agent` 将消息变换、转 LLM 消息与事件执行分开；`packages/coding-agent/src/capability/index.ts` 以 provider、优先级、来源元数据和去重组合技能等能力；`docs/system-prompt-customization.md` 将静态提示块置前、工作区动态内容放到尾部；`docs/memory.md` 把摘要、学习与存储后端分开，记忆作为可被当前仓库证据推翻的背景；`.omp/skills/` 包含 `semantic-compression`、`system-prompts`、`tool-prompt-optimization`。
- Aharou 并非空白：fork44 已有 `ContextPromptPartitioner`、`RequestPrefixTracker`、按需工具目录/工具搜索、原生上下文记忆库、技能、角色、阶段团队和团队证据机制。候选改动必须证明填补差距，不能重复造轮子。

## 需先验收的两项容器要求

1. 每个 profile 独立的 `runtimeBackend`、旧全局偏好迁移、设备/rootfs 兼容门、远端 SSH 禁用 TAwCroot；从设置/config 写入追到 PRoot/TAwCroot 实际执行参数与测试。
2. 精确环境变量值脱敏：默认开启、单一持久化真源、迁移冲突不丢选择；覆盖同步 Bash、后台终端 start/send/read、会话回传与持久化，且不改用户终端本地原始显示、不将本地环境扩展到 SSH。

初步在 fork44 找到实现及相关测试，但“路径存在”不等于完整；逐入口审计并记录 PROVEN / PARTIAL / MISSING。PARTIAL/MISSING 才进入修复拆解。

## 第一轮：核实与最小落地

1. 建立独立 `2.56` 工作分支/工作树；冻结 fork44 基线 SHA，保留另一工作树所有未提交内容。
2. 建立映射表：上游实际文件/行为 → Aharou 对应实现 → 差距 → 是否采纳/理由/许可。
3. 完成两项容器链路验收，修复确认的缺口，不恢复旧实现。
4. 第一轮修正已证实的工具目录歧义：完整工具名优先精确命中，避免它只作为另 10 个工具的子串时被截断漏选；保留关键词 AND 搜索、10 项上限和执行端权限过滤。
5. 第一轮落实两条可检索原生记忆库规则（`RULE` + `SEARCH`，不常驻注入）：system/tool prompt 设计与缓存前缀边界；语义压缩的保真检查。独立改写，不整段复制上游；补完整 MIT notice，不新增 prompts 运行时，不启用新资产常驻。
6. 第一轮验收：工具碰撞测试确保精确名仍被激活且不激活其它匹配项；两条新默认只以 SEARCH-only 种入；旧收据用户得到新条目且现有用户编辑/停用/删除保持原样；规则正文可被 Context Library 搜索，注入预览不含正文；ContextPromptPartitioner 有固定/变量、REFERENCE、pending 和 TEMPORARY 反例；文档、NOTICE、license 一致。

## 第二轮：基于上游真实源码和第一轮结果重规划

1. 第一轮之后再读一次上游 main 实际源码（已记录 commit SHA）与 Aharou 工作树净差异，盲审第一轮记忆条目的重复/过度压缩风险。
2. 核查 OMP 静态 system blocks、末尾 project context、memory snapshot 与 capability discovery，对照 Aharou 的 `ContextPromptPartitioner`、`RequestPrefixTracker`、Context Library、ToolRegistry 和 Team/Skill repositories。
3. 对照后发现 Aharou 已有 stable/dynamic context 分区但之前缺独立纯函数测试；已补 test-first 分区反例，验证固定规则/system prefix 在变量变化时不漂移、动态内容留在 request data，REFERENCE/pending/TEMPORARY 不进固定前缀。
4. 纳入用户补充功能：每个 AI provider 配置“限制并发请求”开关，开启后弹出数字输入。每供应商持久化 `maxConcurrentRequests`（0=不限，正值 1..32），写入 `ai_providers` 第 82 号 Room migration，并纳入配置通道与备份导入/导出。provider id 是全局限流键，同 provider 跨会话/主对话、标题、压缩、视图/手机工具和审查共用名额；不同 provider 独立。默认关闭，旧数据库/旧备份不改变无限制行为；异常/取消均归还槽位。限制的是模型 HTTP/流式请求完整生命周期；排队不占活动名额，不改变网络重试次数和工具并行语义。
5. 第二轮验收：fake provider + 可控阻塞请求测 `limit=1` 排队、`limit=2` 最大活动、不同 provider 独立、两个 adapter 同 provider 共享、异常/取消归还、关闭不限并发；Room 81→82 迁移旧 provider 得 0，实体/配置/备份往返保持设置；UI 开启后必须弹窗输入、取消不改值、保存后退出页持久化；配置 API 上下界有效。所有 AIProvider 请求入口都要共用请求门，直接 HTTP 模型请求另行审计；若有遗漏，应收窄功能范围而非宣称全覆盖。缓存命中仍只报供应商 usage。



## 审查与发布门

- 代码审查者独立于实现者；覆盖正确性、生命周期/并发、隐私、提示词缓存与工具权限、数据迁移、无障碍/文案及变更范围。缺陷审查逐个关联受影响调用链，不以测试通过代替代码审查。
- 项目门禁按仓库脚本实际执行：架构、迁移、技能、资源与 prompt/asset 检查；禁止跳过测试、缩小覆盖或制造假绿。
- 本地 Gradle 遵守一次性 build-allowed 闸门；无有效授权时不跑本地 Gradle，使用目标 SHA 对应 GitHub Actions 构建/单测。
- 发布完成判据：目标提交在 `fork/main`，目标 `v2.56.0-fork.N` 标签指向该提交；对应 CI 与 Android Release 成功；Release 资产含 ARM64 APK、映射和约定审计资产；Docs Deploy 如失败则先查根因并单独复验，最终对账 Release URL/资产 SHA。

## 失败路径与停止条件

- 目标上游 SHA/许可证或 fork 基线无法核实时，不复制内容；改以设计借鉴并标未验证。
- 容器需求已完整满足时不改容器代码，只保留验收证据；缺失则仅修对应调用链。
- 代码审查发现阻断级缺陷、迁移风险或测试无法可靠执行时，不打正式 tag；修复并重新跑目标 SHA 的完整 CI。
- 当前活动工作树的未提交内容保持原样；只在隔离的、从 fork44 派生的交付树工作。
