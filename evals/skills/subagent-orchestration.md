# 验收用例：团队任务编排（`subagent-orchestration`）

## 应该触发

- 多阶段故障修复先查团队并用现有阶段任务分派，不将原文直接交给某个角色
- 团队中设计、实现、验证职责不同，检查任务能否对应到既有阶段
- 多专业审查或验收任务先查团队介绍，再按可运行流程提交目标

## 不该触发

- 「这个函数什么意思」—— 简单、原子任务由主代理直接回答
- 团队不可用时不伪造派发、不用臆造的 task action

## 验收点

- [ ] 先查询团队介绍，并选取当前 schema 中可运行的团队
- [ ] 对多阶段任务明确通过团队预设任务 prompt 分工，没有把用户原文当成员唯一任务
- [ ] `goal` 保留结果目标、工作范围与可验证验收条件
- [ ] 只调用真实支持的 `teams` / `team_run` / `team_assign` 动作
- [ ] 简单原子任务不强制绕团队；无可用团队时准确说明
- [ ] 根据执行终态和结果证据判断交付，不采信空成功

## 怎么手工验

让它「派两个子代理分别查 A 和 B」，看它是否先报计划、prompt 是否自带上下文；中途手动停掉一个，确认它不会偷偷再派。
